## 开始之前：这份自测怎么用

**1. 为什么有上机题（本自测共 3 道，第 8–10 题）。**
选择题能猜、能抄，做完你和教师都不知道你到底会不会。上机题的产出——**一条命令、一份 `read_counts.tsv`、一个能提交成功的 SGE 脚本**——直接反映能力，而且**正是你第一次实践课开场就要用的东西**：硕士 m02 组装、博士 p05 后 GWAS 筛选、本科 u08 项目的第一小时，用的就是这三样。做完这份自测，你不是"考过了"，你是把第一节实践课的准备工作提前做完了。

**2. 计分方式：完成即给分，不按对错计。**
这个设计是刻意的。目的是**拿到诊断数据**，不是筛人——教师看的是全班错在哪，好在首课用 15–20 分钟只过集中出错的点，不重讲、不补课。按对错计分会让人抄答案，错题分布随之失真，这个闸门就废了。

**3. 所以参考答案就直接附在文末（`## 参考答案与评分要点`）。**
既然不按对错计分，抄答案没有任何收益；而公开答案让这份自测同时是一份**学习工具**——你可以先做、再对、再回材料补。**但请先自己做完再翻**：你写下的错误答案，比正确答案更有诊断价值。

**4. 请如实记录卡点。** 任何一题做不出来，就在该题下面写"卡在哪一步、报什么错"。这比蒙对答案有价值得多，它直接决定首课讲什么。

**5. 通过标准**：10 题全部作答（含 3 道上机题的提交物）即视为完成。
三层学生做同一份题；诊断参考线（**本科 ≥ 80%、硕/博 ≥ 60%**）只供教师看错题分布，**不计入成绩**。

**提交方式**：新建一个文本文件 `l0_01_<你的学号>.md`，按题号写答案；上机题把**命令原文 + 输出**粘进去，另附要求的文件。

## 第二部分：上机题（第 8–10 题）

> **这三题必须真的在集群上跑。** 提交物写清楚：命令原文 + 实际输出（前几行即可）。

### Q8（上机 ★ 出口能力：批量处理文件 + 文本处理）

**给定一个混乱的测序文件目录，写一条命令统计每个样本的 read 数。**

先在集群上造出这份目录（**任何账号都能造，不依赖公共数据**）：

```bash
mkdir -p /d3/scratch/${USER}/l0_selftest && cd /d3/scratch/${USER}/l0_selftest
for s in A01 A02 B07 B08; do
  for L in L001 L002; do
    n=$(( (RANDOM % 20 + 5) * 4 ))
    yes $'@r\nACGTACGTAC\n+\nIIIIIIIIII' | head -n "$n" | gzip > "${s}_${L}_R1.fastq.gz"
  done
done
touch README.txt sample_sheet.csv          # 目录里混着无关文件，这才是"混乱"
ls
```

**要求**：写出**一条命令**（可以是一行 `for` 循环 + 管道），输出两列制表符分隔的
`样本名 <TAB> read 数`，**同一样本的两条 lane 要合并计数**，并把结果写进 `read_counts.tsv`。

**提示**：FASTQ 每条记录 4 行；`.gz` 用 `zcat` 直接读；`$( )` 把命令的输出当值用。

**提交物**：
1. 你用的完整命令；
2. `read_counts.tsv` 的**全部内容**（4 行）；
3. 一句话说明：如果目录里还混着 `.fastq.gz` 以外的文件（如 `README.txt`），你的命令为什么不会把它们算进去。

### Q9（上机 ★ 出口能力：提交集群作业）

把第 8 题的统计**改写成 SGE 作业脚本**并成功提交。

**要求**：脚本必须包含 `#$ -S`、`#$ -N`、`#$ -cwd`、`#$ -j y` 四个头，且第一行输出 `hostname`。

**提交物**：
1. 完整脚本内容；
2. `qsub` 的返回信息（形如 `Your job 12345 ("...") has been submitted`）；
3. `qstat -u $USER` 的一次输出；
4. **作业日志的前 3 行**——这是本题的关键采分点：**日志里的主机名必须不是登录节点**。如果是登录节点，说明你没真的提交，回材料 §「核心内容 4」重看。

### Q10（上机 ★ 出口能力：在远程服务器上组织项目目录）

为你**自己接下来要处理的一批真实数据**（毕业课题数据、师兄师姐的数据，或你感兴趣的某个公共数据集）在集群上建立项目目录，并写一份 150–250 字的准备方案。

**提交物**：
1. `mkdir -p` 的命令原文 + `ls -R` 的输出（证明目录已建好，且在 `/d3/scratch/${USER}/` 下）；
2. 150–250 字方案，必须回答四点：① 每个子目录放什么；② 原始数据用什么方式接入、为什么不用 `cp`；③ 哪些步骤必须 `qsub`、哪些可以在登录节点做，判断标准是什么；④ 你打算怎么保证半年后自己还能重跑（脚本放哪、路径怎么写）。

## 参考答案与评分要点

> **先自己做完再看。** 本自测完成即给分、不按对错计——抄答案不会让你多得分，只会让你在第一次实践课上卡住。

**第 1 题** (a) 相对 `../fq/reads.fa`；绝对 `/d3/scratch/${USER}/ngs/fq/reads.fa`（写成 `/d3/scratch/wangys/...` 这种**写死用户名**的形式即为错）。
(b) 写死用户名的绝对路径最容易出错——同学的 `${USER}` 不是你。相对路径只要他也从 `assem/` 出发就没问题；用 `${USER}` 的绝对路径最稳。**要点：脚本里一律用变量与相对路径。**

**第 2 题** 只有 **B 能写**。A 是只读的公共数据区（往里写会 `Permission denied`，也不该污染公共数据）；C 语法上能写，但家目录配额小，30 GB 会撞 `Disk quota exceeded`，中间文件必须放 `/d3/scratch/`；D 大小写错，Linux 区分大小写，`/D3` 根本不存在。

**第 3 题** (a) **错**——报错走 stderr，`>` 只重定向 stdout，要写 `> run.log 2>&1`。(b) **错**——`?` 只匹配恰好一个字符，`s10.fq` 是两个。(c) **错**——`>` 是覆盖，第二次把第一次的内容抹掉了；要叠加用 `>>`。(d) **错**——`zcat` 就是为了不解压直接读。

**第 4 题**
(a) `awk '$3 < 90 {print $1}' stats.tsv`
(b) `awk '{s+=$2} END {print s}' stats.tsv`
(c) `sort -k2,2nr stats.tsv | head -n 3`
（用 `cut`+`sort` 等其他等价写法同样算对。**要点：会按列取数、会数值排序。**）

**第 5 题** (a) ① 登录节点——秒级、无计算量。(b) ③ `qsub`——2 小时 / 12 GB，典型的必须排队的批处理。(c) ② `qrsh`——要反复试、要看即时输出，但不该占登录节点。(d) ③ `qsub`——总计 4 小时，且可并行提交多个作业。
**判断依据**：单步 > 10 分钟、内存 > 2 GB 或需多线程 → `qsub`；要交互调试 → `qrsh`；其余才在登录节点。

**第 6 题** 三处问题：
1. `# -N busco_run` **少了 `$`**，SGE 看不见它，只是普通注释 → 改 `#$ -N busco_run`；
2. `cd /d3/scratch/zhangsan/...` **写死了别人的用户名** → 改 `cd /d3/scratch/${USER}/ngs/assem`（这也是 `Eqw` 的直接原因：目录不存在）；
3. **没有激活 conda 环境**——作业不继承终端环境，`busco` 会 `command not found` → 补 `source /opt/miniconda3/bin/activate` + `conda activate <env>`。
（另可加分项：缺 `#$ -S /bin/bash`、缺 `#$ -j y`、没申请 `-pe smp`。）修正版：

```bash
#!/bin/bash
#$ -S /bin/bash
#$ -N busco_run
#$ -cwd
#$ -j y
#$ -pe smp 4
source /opt/miniconda3/bin/activate
conda activate ngs_ug_assembly
echo "运行节点: $(hostname)"
cd /d3/scratch/${USER}/ngs/assem
busco -i flye.fasta -m genome -l bacteria_odb10 -o busco_out -c 4
```

**第 7 题**
(a) 脚本没有执行权限 → `chmod +x run.sh`（或直接 `bash run.sh`）。
(b) SSH 断开，前台进程被杀 → 事先 `screen -S ngs`（或 `tmux new -s ngs`）；**注意 screen 不解决登录节点资源问题，大任务仍要 `qsub`**。
(c) `scp` 在**服务器上**敲了，它反过来去连你的笔记本 → 到**自己电脑**上敲 `scp 用户名@10.7.254.22:/d3/scratch/用户名/.../result.txt ~/Desktop/`。

**第 8 题** 参考答案（多种写法都对，关键看三点）：

```bash
for s in A01 A02 B07 B08; do
  echo -e "${s}\t$(( $(zcat ${s}_*_R1.fastq.gz | wc -l) / 4 ))"
done > read_counts.tsv
```

或不写死样本名、自动从文件名提取（更好）：

```bash
ls *_R1.fastq.gz | cut -d_ -f1 | sort -u | while read s; do
  echo -e "${s}\t$(( $(zcat ${s}_*_R1.fastq.gz | wc -l) / 4 ))"
done > read_counts.tsv
```

**评分要点**：① 除以 4（FASTQ 每条记录 4 行）；② 同一样本的两条 lane 合并（用 `${s}_*` 通配）；③ 通配符 `*_R1.fastq.gz` 天然排除了 `README.txt` / `sample_sheet.csv`——**这就是第 3 个提交物要回答的**：不是命令"跳过"了它们，而是它们压根没被通配符匹配到。

**第 9 题** 参考脚本：

```bash
#!/bin/bash
#$ -S /bin/bash
#$ -N count_reads
#$ -cwd
#$ -j y
echo "运行节点: $(hostname)"
ls *_R1.fastq.gz | cut -d_ -f1 | sort -u | while read s; do
  echo -e "${s}\t$(( $(zcat ${s}_*_R1.fastq.gz | wc -l) / 4 ))"
done > read_counts_job.tsv
```

**评分要点**：四个 `#$` 头齐全；`qsub` 返回了 job id；**日志第一行的主机名不是登录节点**。如果是登录节点 → 你执行的是 `bash job.sh` 而不是 `qsub job.sh`，这正是首课最需要纠的一条。

**第 10 题** 开放题，无标准答案。合格的方案应当出现：`mkdir -p .../{raw,clean,align,results,scripts,logs}` 这类**按流程分层**的目录；原始数据用 `ln -s` 接入并说明"不复制是因为配额与冗余"；`qsub` 与登录节点的分工给出**可操作的判据**（时间/内存/线程）而不是"大任务就提交"这种空话；可重跑部分提到"脚本进 `scripts/` 并纳入版本管理""路径用 `${USER}` 与相对路径""记录工具版本"。
