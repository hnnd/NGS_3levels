| 项目 | 内容 |
|---|---|
| **对应专题** | `p08` 课题设计与汇报（`02_lectures/phd/topic08_project_design/08_project_design_lecture.md`） |
| **权重** | 占课程总成绩 **47%**（博士层最大的一块，契约 `assessment.materials`） |
| **对象** | **你自己真实的毕业课题**——不发主线数据，不跑新流程 |

## ① 任务背景

这份方案是全课程的收口，也是唯一一份**以你自己的课题为对象**的作业。

p01 教你怎么验证 AI 的输出，p02–p06 各给了你一套组学方法与它的统计边界，p07 教你把这些固化成能被别人重跑的流程。但这七讲加起来仍然回答不了博士毕业时最要紧的那个问题：**面对你自己的科学问题，该用什么数据、按什么顺序做什么分析、做出来的东西怎么变成一篇能发表的论文。**

它占 47%，是因为博士生毕业后需要**独立决定"用什么数据回答什么问题"**，而不是执行别人设计好的流程。讲义 ③ 用两份方案说明了差别：技术驱动的方案（"拟做单细胞 + 空间 + 代谢组 + WGCNA 整合"）在开题时最常见，也最容易在两年后变成一堆跑完了但不知道说明什么的结果；问题驱动的方案先写清一个具体的未知，再选**刚好够用**的技术，并写清失败时怎么办。

**为什么要在方案阶段就画组图骨架。** 组图骨架是方案的验收标准：如果你现在就画不出 Fig.1 到 Fig.6 的逻辑链，说明方案里至少有一环没想清楚——不是"图还没画"，是"论点还不存在"。**先画得出组图骨架，再去测序**，能省掉的往往是半年。

评分表里的「AI 使用与验证记录」占 10%，是契约 `rubric_requirements.ai_verification_log` 对博士层**全部**考核材料的强制要求。本次的 AI 任务（讲义 ⑧）是让 AI 草拟组图骨架与图注，再逐条核查它引用的"同类研究"是否真实存在——**这两件事都无法靠抄完成**。

## ② 交付物

打包为 `学号_姓名_proposal.zip`，解压后目录结构如下（**文件名按此命名，助教按名清点**）：

```
学号_姓名_proposal/
├── proposal.pdf                # 书面方案，正文 8–12 页（按 phd_proposal_template.md 的七节）
├── figure_skeleton.pdf         # 预期组图骨架 Fig.1–Fig.6（按 phd_figure_skeleton_template.md）
├── figure_skeleton/            # 组图骨架的可修改源文件
│   ├── make_placeholder_figs.R # 画占位图的脚本（假数据即可，但必须能跑）
│   └── roadmap.（mmd|drawio|pptx）# 技术路线图源文件，必须可改
├── slides.pdf                  # 汇报 PPT，8–11 页（讲义 ⑤ 步骤 7 的七项内容）
├── ai_verification.md          # AI 使用与验证记录 + 文献真伪核查表
└── self_review.md              # 自评审：④6 四维判据逐条打勾 + 你自己找到的最大弱点
```

各交付物的内容要求：

| 交付物 | 必须包含 | 对应讲义 |
|---|---|---|
| `proposal.pdf` | 七节：科学问题与假说 / 已有证据与空白 / 数据清单 / 技术路线图 / 每个推断节点的统计依据 / 风险与两个 Plan B / 时间表与预期产出 | ⑤ 步骤 1–4、④1、④2 |
| `figure_skeleton.pdf` | 六格 panel，每格四行：图号 / 论点一句话 / 图型与关键元素（含 n、误差棒、统计标注）/ 数据来自路线图第几步；并附"因此"检验结果 | ⑤ 步骤 5、④4 |
| `make_placeholder_figs.R` | 用假数据画出六张占位图并导出。**占位图比手绘草图更容易暴露"这个论点其实画不出来"** | ⑤ 步骤 5 |
| `slides.pdf` | 研究背景 / 数据描述 / 分析技术路线 / **预期组图骨架** / 验证策略 / 风险与备选 / 时间规划 | ⑤ 步骤 7 |
| `ai_verification.md` | AI 原始组图方案与图注 + 你的修改版及每处修改理由 + **文献真伪核查表**（每行：AI 给的引用 / DOI / 解析结果 / 判定真-假-存疑 / 核查方式） | ⑧ 全节 |
| `self_review.md` | 讲义 ⑥ 自评清单八条逐条打勾 + ④6 四维判据 + 一句话写出你自己找到的最大弱点 | ④6、⑥ |

> **课程作图硬规矩**：**所有图中不出现中文字符**。Linux 环境下 R / matplotlib 的默认字体不含中文字形，导出的 PDF 里是方块或缺字（讲义 ⑨-3 有真实报错）。图题、轴标签、图例、注释一律英文；中文解释写在正文。这不是权宜之计——期刊也要求图内文字为英文。

## ③ 完成步骤

**不要重抄讲义**——下面只给路标与本次作业特有的要求。详细方法见讲义 ⑤ 步骤 1–7。

1. **把科学问题压缩成两句话**（先做这个，不要先想技术）。写成"已知 ___，但不知道 ___"，再写一句"如果 ___ 被回答，谁会因此改变做法"。两句都写不出来，回文献。
2. **列数据清单**。每行一类数据：类型 / 样本数 / 分组与重复 / 时间点 / 测序策略与深度**及其依据** / 已有还是待产出 / 批次信息 / 存放位置。**"深度依据"一栏不许写"参考文献常用"**——写清是按什么算出来的。
3. **画技术路线图（DAG）**。每个节点写全"输入 → 工具（版本）→ 关键参数 → 输出 → 预期结果 → **结果不对时长什么样**"；标出哪些节点必须等全部样本到齐。**路线图和 Nextflow/Snakemake 的 DAG 是同一个东西的两种画法**（p07 ④2）。
4. **给每个推断节点标注统计依据**。逐节点填：用什么检验/模型 → 为什么是它 → 阈值是多少 → 假阳性风险在哪 → 对应哪一讲的统计插件（p02 / p04 / p05 / p06）或 `l0_06_stats`。**这一栏空着的方案不予评审**（讲义 ⑦ 的三个可检查动作之一）。
5. **搭组图骨架**，然后做"因此"检验：在相邻两张图之间插入"因此"读一遍，读不通就是缺图、顺序错，或那两张图本就是并列而非递进。
6. **做 AI 任务**（讲义 ⑧）。让 AI 草拟 Fig.1–Fig.6 与图注并要求它给出"同类研究"的作者、年份、期刊与 DOI；然后按四条动作核查。**文献核查用 DOI 解析 + Crossref 元数据比对 + 标题反查三步**，判定分真 / 假 / 存疑三档。注意反向陷阱：有些 DOI 能解析，但落地的是另一篇文章，**只看状态码不够，必须比对标题作者**。
7. **自评审**。按 ④6 四维判据逐条打勾，写下你自己找到的最大弱点——**主动写出弱点不扣分，掩盖弱点被问出来才扣**。
8. **汇报**（8 分钟 + 4 分钟问答），会后按反馈修改并交终稿。

> **8 分钟怎么分配**（时间控制本身是评分项）：背景 1.5 min → 数据 1 min → 路线 2.5 min → **组图骨架 2 min** → 风险与验证 1 min。**组图骨架必须讲**，它是本讲区别于一般开题的地方。
>
> **问答的应对**：把问题分三类——① 我知道答案 → 直接答；② 我没想过但能当场判断 → 说清判断依据并承认是现场推断；③ 需要查证或补做 → **明确说"这个我需要回去核实"并记下来**。第三类如实说不扣分，**硬编答案扣分**。

## ④ 评分标准

总分 100，折算为课程总成绩的 47%。

> **本表与大纲五维度的关系**：讲义 ⑥ 与大纲原表为五维度（问题清晰度 20 / 方法合理性 30 / 技术细节 25 / 创新性 15 / 汇报表达 10）。契约 `rubric_requirements.ai_verification_log` 规定「AI 使用与验证记录」是博士层**全部**考核材料的强制评分栏，故本表在五维度基础上插入该栏（10），**原五维等比压缩至 0.9 倍并取整**（20→18、30→27、25→23、15→13、10→9）。**压缩后维度间的相对次序完全不变：方法合理性仍是权重最高的维度**——博士层考核的是设计与判断，不是创新点的数量。AI 栏定为 10 而非 20，是因为它考的是**判断力抽查**，不应与「方法选择与结果可信度说明」（30）同量级。大纲 `syllabus_phd.md` §课题方案评分标准 与讲义 ⑥ 已同步为本表。

| 评分维度 | 权重 | 评分要点 |
|---|---|---|
| **问题清晰度** | 18 | 能写成"已知 A，不知道 B"；能说清 B 被回答后**谁会改变做法**；能回答"为什么必须用组学而不是 qPCR / 表型观察 / 公共数据重分析" |
| **方法合理性** | 27 | 每一步有工具与参数；**每个推断节点都标注了统计依据与假阳性风险**（空栏不予评审）；样本量有功效依据；重复是生物学重复；批次与协变量已识别 |
| **技术细节** | 23 | 路线图每个节点写全"输入→工具（版本）→参数→输出→预期结果→结果不对时长什么样"；组图骨架六格填满且通过"因此"检验；**两个具体到可立刻执行的 Plan B**（"换一种方法"不算） |
| **创新性** | 13 | 分析思路是否有超出标准流程的地方；是否设计了排除替代解释的证据（Fig.5 位） |
| **汇报表达** | 9 | PPT 质量（含组图骨架的逻辑链）、**组图骨架必须讲**、时间控制、问答分类应对 |
| **AI 使用与验证记录** | 10 | 见下方四条核查动作 |

### 「AI 使用与验证记录」的四条核查动作（契约 `ai_verification_log`）

每条都要写出**结论**，不是写出"我做了"。四条各约 2–3 分：

| 要核查什么 | 本任务的落点 | 不合格的写法 |
|---|---|---|
| **1. 组图是否成链** | 在 AI 给的相邻两图间插"因此"。AI 极易产出"PCA→火山图→GO→KEGG→热图→qPCR"这种**按分析流程排列**的堆放——读起来很顺，但那是流程顺，不是论证顺 | "AI 给的组图逻辑清晰" |
| **2. 每张图的论点你的数据支持得了吗** | 逐图回到路线图找出数据来自哪一步。AI 会自信地安排你根本没有的数据（只有 bulk 却给你排了单细胞图） | 不回溯路线图，直接采纳 |
| **3. 它引用的每篇"同类研究"是否真实存在** | 逐条 DOI 解析 + Crossref 元数据比对 + 标题反查，判真 / 假 / 存疑，填进核查表 | 只贴 AI 原文，或只写"已核实" |
| **4. 图注是否含 n、统计方法、误差棒定义** | 逐条对照讲义 ④5。AI 的图注常写得漂亮但缺 n 和检验方法——**因为它不知道你的 n** | 直接沿用 AI 图注 |

> **若 AI 这次恰好没编造文献，也要提交完整核查表证明你查过**——"没发现问题"和"没查"在提交物上必须可区分。若某一环确实未用 AI，写明"未使用"及原因即可，不扣分；但通篇声称 AI 输出全部正确且无验证过程的，本栏不得分。

## ⑤ 提交方式与截止

方案分**四个阶段**推进。前两阶段不单独计分，但**未按时交 S1 与 S2 者不得进入 S3 课堂汇报**，「汇报表达」一栏按 0 计。

| 阶段 | 截止 | 交什么 | 用途 |
|---|---|---|---|
| **S1 选题确认** | p05 课后第 7 天 23:59 | 一页纸：科学问题两句话 + 数据清单初版 | 教师回一条书面意见；把方向错了的人尽早拦下来 |
| **S2 方案初稿 + 组图骨架** | **p08 上课前 3 天** 23:59 | `proposal.pdf` 初稿 + `figure_skeleton.pdf` | 课堂互评要用；随机分配给一位同学做同行评审 |
| **S3 课堂汇报** | p08 第 3–4 学时 | `slides.pdf`（8–11 页） | 每人 8 分钟汇报 + 4 分钟问答 |
| **S4 终稿** | p08 课后第 **10** 天 23:59 | ② 的全部交付物 | 按此评分 |

- **提交入口**：课程 LMS「课题方案设计」；文件名 `学号_姓名_proposal.zip`（≤ 100 MB）
- **同行评审**：S2 后你会收到一位同学的方案，按讲义 ④6 四维判据逐条打分，并给出**一条具体到可执行**的改进意见——"建议增加样本量"不算，"建议把 24 h 单时间点改为 12/24/48 h 三点，否则无法区分是响应延迟还是无响应"才算。评审意见随 S4 一并提交，计入「汇报表达」。
- **迟交**：S4 迟交 3 天内按 90% 计，超过 3 天按 70% 计，超过 7 天不计分（可申请一次不扣分延期，须在截止前提出）
- **重交**：允许在各阶段截止前重复提交，以最后一次为准
- **诚信**：方案必须是你**自己真实的课题**；可与导师、同学讨论，但书面方案与组图骨架须独立完成。直接提交他人方案或课题组已有的开题报告原文按学术不端处理。**允许并鼓励用 AI 辅助，但必须如实填写 `ai_verification.md`。**

## ⑥ 常见失分点

前三条来自讲义 ⑥ 的三种失败形态（评审现场最常见），后四条来自讲义 ⑨ 的评审原话与真实报错：

| # | 失分点 | 长什么样 | 怎么自查 |
|---|---|---|---|
| 1 | **技术堆叠型方案** | 路线图上有单细胞、空间、代谢组、蛋白组四条线，但每条线的"预期结果"栏都写着"筛选差异分子" | **把任意一条技术线删掉，科学问题的回答会变得不完整吗？** 不会就说明这条线是装饰 |
| 2 | **组图不成链型** | Fig.1 PCA → Fig.2 火山图 → Fig.3 GO → Fig.4 KEGG → Fig.5 热图 → Fig.6 qPCR。看起来完整，实际是一条标准分析流程的输出顺序 | 相邻两图之间**只能插"另外"、插不进"因此"**；通病是没有任何一张图在排除替代解释 |
| 3 | **无失败预案型** | "风险与备选"一页写着"如遇问题及时与导师沟通" | 指着路线图上**耗时最长**的那一步问"它失败了你怎么办"，答不出具体动作即不合格 |
| 4 | **图注只描述、不陈述论点**（⑨-5「这张图想说什么？」） | 图注第一句是"X 的表达热图"而不是可被证伪的陈述句 | 把图注第一句读出来：是"…的热图"就还没有论点；是"处理组在 24 h 特异激活了 JA 通路，n=3，双侧 Wilcoxon，误差棒为 SEM"才有 |
| 5 | **图注三要素缺失**（⑨-7「n 是多少？误差棒是什么？」） | 最容易避免也最常被扣分：n、统计方法、误差棒定义缺一即触发 | 做一个图注模板，每张图套一遍 |
| 6 | **样本量无依据** | 方案写"每组 n=3"，问为什么不是 6 答不出 | 写"依据可得样本上限"是**诚实且可接受的**；不写任何依据不可接受（讲义 ⑦ 动作 1） |
| 7 | **图里出现方块 / 缺字**（⑨-3） | `conversion failure on '处理组' in 'mbcsToSbcs'`；屏幕预览可能正常，导出 PDF 才发现 | 课程规矩：图中一律不用中文，交稿前把 PDF 放大到 400% 逐图看一遍 |
| 8 | **AI 编造的文献被原样写进方案**（⑨-1） | Crossref 返回 `Resource not found.`；DOI 形状完全合法（`10.1038/` 是真前缀）但后缀是编的 | 不要止步于"DOI 打不开可能是网络问题"；标题去 PubMed 反查，搜不到就判**假**并记录 |

### 交稿前自评清单（讲义 ⑥，逐条打勾后随 `self_review.md` 提交）

- [ ] 科学问题能写成"已知 A，不知道 B"
- [ ] 每个技术选择都能回答"为什么不是更便宜的手段"
- [ ] 数据清单里每一行都有深度依据与批次信息
- [ ] 每个推断步骤都标注了统计依据与假阳性风险
- [ ] 组图骨架的相邻两图之间都能插入"因此"
- [ ] 每张图注都含 n、统计方法、误差棒定义
- [ ] 至少两个具体到可执行的 Plan B
- [ ] 图中没有任何中文字符
- [ ] **如果方案全部做完但结果全是阴性，这篇论文还能写吗？写什么？**（讲义 ⑩-7⑥：答不上来说明方案的价值全部押在一个未知的结果上，这是设计缺陷，不是运气问题）
