## ① 任务背景

这是全课程唯一一次**没有分析流程可跑**的作业，因此也最容易被低估。讲义头部写得很直白：这一讲考的是判断力。

后面七个专题都建立在"数据本身是对的"这个前提上——而这个前提在 m01 就决定了。一份混杂的设计（各组分不同日期送测）无论后面用多好的方法都救不回来：讲义 ④ 4.6 说明了这是**设计矩阵秩不足**，不是统计方法不够好。同样，把同一 BioSample 的多个 Run 当成生物学重复（⑤ 5.1 的常见误区），会让组内方差被人为压低、p 值系统性偏小，而这一切**不会有任何报错**。

本次作业有两个产出：一份你自己课题的**测序方案**，和一份从公共数据检索、下载、验收后整理出的**标准 sample sheet**。后者的格式被 `m02`–`m08` 全部复用，现在做规范了，后面七次作业都省事。

> **本专题不在统计插件名单内**（讲义 ⑦ 已写明「本讲无独立统计要点」）。实验设计所需的统计能力已整体归入 `l0_06_stats`，本次作业**不设**「方法选择与结果可信度说明」评分项——但重复数与深度的**依据来源**仍按「规范性」评分（见 ④）。

## ② 交付物

打包为 `学号_姓名_m01.zip`，解压后目录结构如下（**文件名按此命名，助教按名清点**）：

```
学号_姓名_m01/

├── sample_sheet.tsv            # 标准格式，8 列（见下）

├── verify_log.txt              # 5.4 四步验收的命令与输出（原样粘贴，不要手抄）

└── figs/                       # 若有图，标题/轴/图例一律英文（课程规则）
    └── fig1_batch_design.png   # 组 × 批次交叉表的可视化（可选，也可用表格代替）
```

**`sample_sheet.tsv` 的 8 列**（讲义 ⑤ 5.5 定义，`m02`–`m08` 复用此格式）：

```
sample_id  group  replicate  batch  platform  layout  run_accession  depth_gb
```

`group` 与 `replicate` **必须人工从文章正文或 BioSample 描述回填**——公共数据的分组信息经常只写在正文里，元数据字段是空的。这一步没法自动化，也正是本次作业的核心练习。

**`design_proposal.pdf` 的六段式结构**（讲义 ⑤ 5.6）：

| 段 | 内容 | 对应讲义 |
|---|---|---|
| 1 科学问题与假设 | 一句话，**必须可证伪** | ⑥ 6.5 |
| 2 平台与文库选型 | 四维判据取至少两维 + **写明放弃了什么** | ④ 4.2、4.3 |
| 3 样本量与重复数 | 生物学重复的独立性来源 + 重复数依据的来源 | ④ 4.4 |
| 4 测序深度 | `基因组大小 × 目标深度 ÷ 有效比例` 的换算式 + 有效比例来源 | ④ 4.5 |
| 5 批次与随机化 | **组 × 批次交叉表** + 元数据字段清单（≥ 6 项） | ④ 4.6 |
| 6 预算与风险 | 单价 × 数据量 + 失败重测预留 | ⑤ 5.6 |

## ③ 完成步骤

**不要重抄讲义**——下面只给路标与本次作业特有的要求。

1. **选一个公开 BioProject**。用课程提供的编号，或自己找一个：要求样本数 ≥ 6、双端 Illumina、且**正文或补充材料里能查到分组信息**。选定后先在 ENA 网页确认它是公开的（讲义 ⑨-E1：查不到就是没公开，不是网络问题）。
2. **检索元数据**（⑤ 5.2）。**优先用 ENA Portal API**——它返回 TSV 且带 `fastq_md5` 字段，而 NCBI 的 runinfo 拿不到这个字段，没有它第 4 步的验收做不了。
3. **看清 BioSample → Run 的映射**（⑤ 5.1）。一个 BioSample 对应多个 Run 时，那是同一文库跑了多个 lane，是**技术重复**。把它们当成生物学重复是本讲最想让你避开的错误。
4. **下载 1–2 个 Run**（⑤ 5.3）。全部下完既没必要也占配额。**必须 `qsub` 提交**（⑨-E4：登录节点跑几小时会被静默杀掉），`prefetch` 显式给 `-O`（⑨-E2），`fasterq-dump` 显式给 `-t`（⑨-E3）。
5. **走完 5.4 的四步验收**：MD5、read 数、双端行数相等、读长与平台自洽。**把命令与输出原样粘进 `verify_log.txt`**——手抄的数字不算证据。
6. **整理 sample sheet**，人工回填 `group` 与 `replicate`。若某个样本的分组实在查不出来，在报告里写明查证过程与结论（⑨-E8：映射不出来的数据集不该用）。
7. **写你自己课题的方案**（⑤ 5.6 六段式）。这一段与上面的公共数据练习是**两回事**：练习是为了让你熟悉元数据与验收，方案写的是你自己的课题。

> **允许用 AI 辅助**，但方案里的每一个判据必须是你能当场辩护的。硕士层不强制提交 AI 验证记录（那是博士层 `ai_verification_log` 的要求）；若 AI 编造了不存在的 accession 或深度经验值，按「规范性」扣分。

### 方案验收表（讲义 ⑥ 6.5，助教按此逐条打勾）

- [ ] 科学问题是**可证伪**的陈述，不是"研究 X 的机制"
- [ ] 平台选型给了**至少两维**判据，并写明"这个选择放弃了什么"
- [ ] 明确区分生物学重复与技术重复，并说明生物学独立性从何而来
- [ ] 重复数有依据（预实验离散度 / 同类文献 / 功效计算），不是"一般都用 3"
- [ ] 深度做了 `基因组大小 × 深度 ÷ 有效比例` 的换算，有效比例注明来源
- [ ] 给出**组 × 批次交叉表**，且每个批次含全部处理组
- [ ] 元数据字段清单 ≥ 6 项（建库日期、操作人、试剂批号、仪器与 lane…），预算含失败重测预留
- [ ] 写明这份数据最终会走进本课程的哪一讲（`m02`–`m08`）

## ⑥ 常见失分点

来自讲义 ⑨ 与 ⑥ 6.4 的真实问题，**按出现频率排序**：

| # | 失分点 | 长什么样 | 怎么自查 |
|---|---|---|---|
| 1 | **把多个 Run 当成多个生物学重复**（⑤ 5.1、⑥ 6.4） | 不报错；同一"重复组"的样本在后续 PCA 上分成两簇 | 回查 BioSample → Run 映射；一个 BioSample 的多个 Run 是技术重复，合并而非并列 |
| 2 | **验收没走完就当下载成功**（⑨-E7） | 静默错误：`--split-files` 与 `--split-3` 混用，或只下了 `_1`，拿到一半 read | 坚持四步验收并把它写进脚本；`_1` 与 `_2` 行数必须相等 |
| 3 | **`prefetch` 写爆家目录**（⑨-E2） | `Disk quota exceeded`，或 `can't open '/home/user/ncbi/public/sra'` | 永远显式 `-O /d3/scratch/$USER/...`；`fasterq-dump` 另给 `-t`（临时空间约需最终 FASTQ 的 10 倍，⑨-E3） |
| 4 | **在登录节点跑下载**（⑨-E4） | **无报错**，进程几小时后消失 | 用 `qsub` 提交（`01_fetch_sra.sh` 已带 SGE 头）；作业里必须重新 `conda activate`（⑨-E5） |
| 5 | **`group` 字段留空或写 TBD**（⑨-E8） | sample sheet 交上来 `group` 全是 `TBD` | 回文章正文与 Supplementary 手工映射；映射不出来就换数据集 |
| 6 | **重复数写"一般用 3"** | 方案第 3 段没有依据来源 | 必须写出依据从哪来：预实验离散度 / 同类文献 / 功效计算，三选一 |
| 7 | **深度只给数字不给换算** | 写"测 30×"就没有了 | 必须写 `基因组大小 × 深度 ÷ 有效比例`，并注明有效比例是预实验值、文献值还是公司承诺值 |
| 8 | **组 × 批次完全一一对应**（⑥ 6.4 最后一行） | 交叉表是对角矩阵——**设计本身就是混杂的** | 交叉表一看便知；此时该改设计或换数据集，不是换分析方法 |
| 9 | **忽略 `instrument_model` 混用**（⑥ 6.2） | 同一 BioProject 里出现两种机型，没记进 sample sheet | 同一项目两种机型 = 潜在批次，必须作为 `batch` 列的依据之一 |
