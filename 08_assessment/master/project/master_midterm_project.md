# 硕士期中项目：一条组学线的完整走通

| 项目 | 内容 |
|---|---|
| **权重** | 占课程总成绩 **22%**（契约 `assessment.materials`；大纲 `01_syllabus/syllabus_master.md` §课程评估） |
| **可选范围** | m02 基因组组装与比较 / m03 重测序与变异检测 / m04 转录组 / m05 转录调控与表观组 —— **四选一** |
| **布置时间** | m05（专题 5）结束后 |
| **提交时间** | m07（专题 7）结束时 |
| **报告模板** | `master_report_template.md`（同目录） |
| **建议用时** | 上机 12–20 小时（视所选组学线），写报告 4–6 小时 |

## ① 任务背景

前五个专题里，你每次只走了一条线的**一段**——m04 的作业从 counts 矩阵开始，m03 的作业从已经比对好的 BAM 开始。期中项目要求你**从原始数据一路走到可以放进论文的图**，中间不许断链。

这么设计的理由是：硕士层的考核重心是**流程完整性**（大纲原话）。不是看你能不能想出新方法（那是博士层的要求），也不是看命令敲得规不规范（那是本科层的要求），而是看你**能不能把一类数据从原始文件一路走到可写进论文的结果，中间不断链、每一步都说得清为什么**。

断链最常发生在交接处，而交接处恰恰是单次专题作业覆盖不到的地方：质控合格线怎么定才不影响下游、比对率多少算能往下走、上游参数的选择怎样一路传播到最后那张图。这次要把这些接缝自己走一遍。

期中项目同时是期末项目的**预演**：期末要用**你自己课题的数据**做同样的事，并且额外交一个可一键重跑的包（m08 的内容）。这次先用课程数据把方法论跑顺。

## ② 交付物

打包为 `学号_姓名_期中项目.zip`，解压后结构如下（**文件名按此命名，助教按名清点**）：

```
学号_姓名_期中项目/
├── report.pdf              # 主报告，正文 10–15 页（不含附图），按 ③ 的五段结构
├── scripts/                # 从原始数据到最终图的**全部**命令与脚本，按执行顺序编号
│   ├── 01_*.sh
│   ├── 02_*.sh
│   └── ...
├── results/                # 关键结果表（不要交 BAM / FASTQ / 索引）
├── figs/                   # 至少 5 张图，标题/轴/图例一律英文（课程规则）
├── logs/                   # 关键步骤的日志或 QC 报告（fastp/MultiQC/flagstat 等）
└── env_snapshot.yml        # conda env export --no-builds
```

报告正文必须含以下五段，**这就是"完整走一遍"的定义**（大纲：数据获取 → 质控 → 主分析 → 结果解读 → 图表产出）：

| 段 | 内容 | 不能跳过的原因 |
|---|---|---|
| 1 数据获取与实验设计 | 数据来源（课程数据或公开数据，给出登录号或路径）、物种、样本数、分组、建库方式；**设计的局限先写在这里** | 后面每个统计判断都要回来引用这一段 |
| 2 质控与预处理 | QC 指标、过滤参数与理由、过滤前后数据量；**异常样本的处置决定**（剔除须具名） | 静默丢样本是本课程明令禁止的 |
| 3 主分析 | 所选组学线的核心步骤与参数；每个关键参数写出选择依据 | 参数依据是「方法可信度说明」的原料 |
| 4 结果解读 | 结果说明了什么生物学问题；**并给出"结果不对时长什么样"的自查**（各专题讲义 ⑥ 都有这一节） | 只讲正确结果的报告，遇到异常时无从判断 |
| 5 **方法选择与结果可信度说明**（≤ 2 页） | 见 ④ 的四问 | 大纲规定的评分维度 |

## ③ 完成步骤

**四条线选一条，走完全程。** 各线的最低要求如下（详细操作回各专题讲义 ⑤，不要重抄）：

| 线 | 起点 | 必经步骤 | 终点交付 |
|---|---|---|---|
| **m02 基因组** | 原始 reads | k-mer 特征估计 → 长读长组装 → QUAST + BUSCO 评估 | 组装统计表 + 连续性/完整性判读；若做泛基因组，另加核心/可变基因组成 |
| **m03 变异** | 原始 reads | 比对 → 去重 → 变异检测 → 过滤 → 注释 | 变异数、Ti/Tv、**阈值敏感性表**、HIGH 影响变异清单 |
| **m04 转录组** | 原始 reads | 质控 → 定量 → DESeq2 → 富集 | 差异基因表、火山图/热图、富集结果（`universe` 必须写明） |
| **m05 调控组** | 原始 reads | 质控 → 比对 → peak calling → 注释 / motif | QC 指标表（比对率、重复率、FRiP、TSS enrichment）、peak 注释分布、Top motif |

通用要求：

1. **数据可以自带**。用你自己课题的数据做期中项目是**推荐**的——期末项目要用同一套数据，现在做等于提前开工。自带数据须在第 1 段写明来源与建库方式。
2. **上游参数要能回溯**。把每一步的实际命令按顺序存进 `scripts/`，不要事后凭记忆重写。**这一条在期末项目会升级成"必须能一键重跑"**（m08 的内容），现在先养成留痕的习惯。
3. **长作业一律 `qsub`**。组装、比对、peak calling 都不要在登录节点跑。
4. **先看诊断图再看结果图**。每条线都有自己的第一诊断依据（m03 的比对率与 callable region、m04 的 PCA 与 `plotDispEsts`、m05 的 FRiP 与 TSS enrichment、m06/m07 的 track 表与 CheckM2）。**先看结果图的人会把技术问题当成生物学发现。**
5. **图表标签一律英文**，中文解释写在正文（课程规则；集群 R 环境的中文字体会渲染成方块）。

> **允许用 AI 辅助写代码**，但报告里出现的每个数字必须是你自己跑出来的。若 AI 生成的代码导致了错误结论，按「结果正确性」扣分，不因"是 AI 写的"减免。

## ④ 评分标准

总分 100，折算为课程总成绩的 22%。**评分维度与大纲 §课程评估「期中项目」一致。**

| 评分维度 | 权重 | 评分要点 |
|---|---|---|
| **流程完整性** | 35 | 五段结构齐全；**从原始数据到最终图不断链**（`scripts/` 能对应上报告里每一个数字）；日志与 QC 报告留存；异常样本有具名处置；环境快照齐全 |
| **结果正确性** | 25 | 参数与数据类型匹配；矩阵/文件格式用对；诊断指标判读正确；结论与证据一致（不出现"图里是下调、文字写上调"这类错位） |
| **方法选择与结果可信度说明** | 25 | 见下方四问，**评分不看结论对不对，看推理链是否闭合** |
| **图表与报告质量** | 15 | ≥ 5 张图且每张都有明确论点；图表编号与标题规范；标签为英文；正文行文清晰，篇幅控制在 10–15 页 |

### 「方法选择与结果可信度说明」的四个问题

两页之内回答完，每问约 6 分。这是契约 `rubric_requirements.method_justification` 的四问在期中项目上的落点（本项目不属 `stats_plugin_topics`，权重按大纲取 25 而非 30）：

| 要回答的问题 | 期中项目的落点 | 不合格的写法 |
|---|---|---|
| **1. 为什么用这个检验 / 模型 / 工具？** | 为什么选这条组学线的这个工具而不是同类替代（Salmon vs STAR、MACS2 的模式、GATK vs bcftools） | "这是常用流程" |
| **2. 为什么用这个阈值？** | 至少挑**两个**关键阈值给出依据，并给出**换一个值会怎样**的实测数字 | "用了默认参数" |
| **3. 假阳性风险在哪？** | 本条线特有的假阳性来源；设计上的混杂（批次、深度、分组不平衡）；样本量够不够支撑你的统计结论 | "结果可靠" |
| **4. 什么证据能推翻你的结论？** | 你会做哪个验证实验、预期哪几个结果最可能不重复、为什么 | "需要进一步验证" |

## ⑤ 提交方式与截止

- **提交入口**：课程 LMS「期中项目」；文件名 `学号_姓名_期中项目.zip`（≤ 300 MB，超出则去掉中间文件，只保留结果表与图）
- **布置时间**：m05 课后当天发布；**截止时间**：m07 课后 **第 7 天 23:59**
- **中期检查（不计分，但强烈建议）**：m06 课上用 5 分钟向助教口头说明"你选了哪条线、走到哪一步、卡在哪"。往届经验是——**在这一步暴露问题的人，最终分数明显更高**
- **迟交**：3 天内按 90% 计，超过 3 天按 70% 计，超过 7 天不计分（可申请一次不扣分延期，须在截止前提出）
- **重交**：允许在截止前重复提交，以最后一次为准
- **诚信**：可与同学讨论方法与排错，但数据处理、结果解读与写作须独立完成。**同一课题组的同学若用同一批数据，必须在报告第 1 段声明，且分析与解读须各自独立完成**；直接提交他人结果文件按学术不端处理

## ⑥ 常见失分点

期中项目的失分与单次专题作业不同——**大多不在某一步做错，而在接缝处断链**。按出现频率排序：

| # | 失分点 | 长什么样 | 怎么自查 |
|---|---|---|---|
| 1 | **链是断的** | 报告里有 QC 也有最终图，但中间某一步的命令没留下来，问起来说"当时是手敲的" | 提交前自问：**给我 `scripts/` 和原始数据，我能重现报告里每个数字吗？** |
| 2 | **只写做了什么，不写为什么** | 通篇"我们使用 X 工具，参数为 Y"，第 5 段写不满一页 | 每个关键参数问一句"换一个值会怎样"，答不上来就是没想清楚 |
| 3 | **跳过诊断直接看结果** | 没有 PCA / 没有 `plotDispEsts` / 没有 FRiP / 没有 track 表，直接给差异表 | 先看诊断图是各专题讲义 ⑥ 的统一要求 |
| 4 | **异常样本静默消失** | 第 1 段说 12 个样本，第 3 段的图上只有 10 个点 | 剔除必须具名并说明理由，这是本课程反复强调的红线 |
| 5 | **图没有论点** | 5 张图都是软件默认输出，图注只写"XX 图" | 每张图问"它支持报告里的哪一句话"，答不上来就删掉或换一张 |
| 6 | **篇幅失控** | 正文 30 页，一半是命令行截图 | 命令进 `scripts/`，正文只留判断与结论；10–15 页是硬要求 |
| 7 | **图里出现方块字** | 中文标题在集群 R 环境下渲染为 □□□ | 课程规则：图内一律英文；中文解释写在正文 |
| 8 | **结论与证据错位** | 文字写"处理组显著上调"，表里 `log2FC` 是负的；或 p 值与图里的分组不对应 | 提交前把正文每个数字与 `results/` 里的表逐一对照一遍 |
