# 硕士期末项目：结合本人课题的分析方案与初步结果

| 项目 | 内容 |
|---|---|
| **权重** | 占课程总成绩 **33%**（契约 `assessment.materials`；大纲 `01_syllabus/syllabus_master.md` §课程评估） |
| **三份材料** | ① 分析方案 ② 初步结果 ③ **可重复包**（按 m08 标准，助教实际执行验收） |
| **布置时间** | m08（专题 8）课上 |
| **报告模板** | `master_report_template.md`（同目录） |
| **建议用时** | 上机 15–25 小时，写方案与报告 6–10 小时 |

## ① 任务背景

期中项目是"用课程数据把方法论跑顺"，期末项目是**"把它用到你自己的课题上"**。

三份材料对应三种能力，缺一都不算完成：

- **分析方案**——你能不能从科学问题出发倒推出需要什么数据、走哪条线、预期产出什么。这一项衔接 m01 的实验设计训练，也是你写开题报告和基金本子时要反复用到的东西。
- **初步结果**——你能不能在**真实的、不干净的**数据上把方案跑出来。课程数据是挑过的，你自己的数据不是：样本量可能不够、分组可能不平衡、批次可能与处理混杂。方案在真实数据上撞墙，本身就是有价值的发现，**如实写出来不扣分，掩盖才扣分**。
- **可重复包**——你交出去的东西，别人能不能跑起来。这一项**由助教在独立环境中实际执行验收，跑不通即该项不得分**（大纲原话）。这是本层次"流程完整性"定位最直接的检验方式，占 25 分，是三项里最硬的一项。

期中项目的中期检查经验在这里同样适用：**早暴露问题的人最终分数更高**。

## ② 交付物

提交一个 **git 仓库归档**（`git bundle` 或含 `.git/` 的 `.zip`），命名 `学号_姓名_期末项目.zip`。三份材料的对应关系如下：

```
学号_姓名_期末项目/
├── proposal.pdf            # 【材料一】分析方案，4–6 页
├── report.pdf              # 【材料二】初步结果，8–12 页（不含附图）
│
├── README.md               # 【材料三】可重复包 —— 这是什么 / 怎么跑 / 产出什么
├── config.yaml             #   全部可变参数与阈值（唯一存放处，随 git 版本化）
├── samples.tsv             #   样本清单，制表符分隔
├── Snakefile               #   3–5 条工作 rule + rule all
├── envs/*.yaml             #   每条 rule 的 conda 环境
├── scripts/                #   参数化后的 shell / R 脚本
├── report/report.qmd       #   参数化 Quarto 报告（尾部固定 sessionInfo() + 环境快照）
├── data/                   #   .gitignore 排除；另附 download.sh 或数据获取说明
├── results/                #   .gitignore 排除；可整个删除后由 snakemake 重建
├── logs/  benchmarks/      #   各 rule 各样本，路径含 wildcards
└── figs/                   #   报告用图，标题/轴/图例一律英文（课程规则）
```

> **目录骨架对齐 m08 讲义**（`data/ results/ scripts/ envs/ workflow/ report/`）。若你把 `Snakefile` 放在 `workflow/` 子目录下，README 里写明启动命令即可，不扣分。

### 材料一：分析方案（proposal.pdf，4–6 页）

| 节 | 内容 | 衔接 |
|---|---|---|
| 1 科学问题 | 你要回答什么，为什么值得回答；**这个问题能不能被测序数据回答** | m01 |
| 2 需要什么数据 | 物种/材料、样本数与分组、建库策略、测序量与理由；**功效或最小可检出效应的估计** | m01、各专题 ⑦ |
| 3 用哪条分析线 | 主路线的每一步与备选工具；为什么选这条而不是那条 | m02–m07 |
| 4 预期产出 | 预期得到哪几张图/哪几张表，各支持哪个论点 | 各专题 ⑥ |
| 5 风险与备选 | **最可能失败的是哪一步、怎么发现、失败了走哪条备选路** | 全课程 |

### 材料二：初步结果（report.pdf，8–12 页）

在已有数据（或公开数据）上跑出的**实际**结果与解读。结构沿用期中项目的五段：数据获取与设计 → 质控 → 主分析 → 结果解读 → **方法选择与结果可信度说明**（≤ 2 页）。

**数据不足时怎么办**：真实课题常常只有 3 个重复、或分组严重不平衡。此时**不要伪造样本数、不要挑好看的子集**。正确做法是：按讲义（如 m06 ⑦-7.5）先算这个设计能不能支持统计判断，报告效应量而非 p 值，并在第 5 节写清限制与后续补样计划。**如实报告限制不扣分；掩盖限制按「结果与解读」重扣。**

### 材料三：可重复包

按 m08 的标准打包，验收标准与 m08 作业一致但更严：助教会**在独立环境中执行**

```bash
snakemake --use-conda -c 4        # 跑通全流程
snakemake -c 1 <你的报告目标>       # 渲染出报告
```

跑不通即「可重复性」25 分不得分。

## ③ 完成步骤

1. **先写方案，再动手**。方案定稿后再跑分析——顺序反了会变成"用结果倒推问题"，第 5 节的风险与备选也就无从写起。方案可以在跑的过程中修订，**但要保留修订说明**（写在 `proposal.pdf` 末尾或 git 提交历史里）。
2. **数据来源三选一**：① 本人课题已有数据（**首选**）；② 课题组内可用的公开数据；③ 与课题最接近的公开数据（须在方案第 2 节说明为什么用它替代、差别在哪）。期中项目已用自己数据的，这次直接接着做。
3. **先把流程搭起来，再跑全量**。用 `make_demo_data.py` 或数据的一个小子集把 Snakemake 跑通，再换全量数据——不要等跑了 8 小时才发现 rule 写错了。
4. **`config.yaml` 是阈值的唯一存放处**（m08 ⑦ 的硬要求）。每次改阈值都 `git commit`，否则你无法回答"这批结果是用哪版参数跑的"。
5. **报告必须是"活的"**：改 `config.yaml` 一个阈值 → 重跑 → 报告数字自己变。做不到说明报告没真正接进流程。
6. **自测可重复性**。提交前把 `results/` 整个删掉，重新 `snakemake --use-conda -c 4` 跑一遍。**这是助教要做的事，你先做一遍。** 再把仓库拷到另一个目录（或换台机器/换个账号）跑一次，能暴露绝大多数硬编码路径问题。
7. **`data/` 不入库**，但要给出获取方式：公开数据给 `download.sh` + 登录号；私有数据给一份 `data/README.md` 说明数据结构与获取途径，并附一份可跑通流程的**微型样例**。

> **允许用 AI 辅助写代码与润色文字**，但方案的科学判断与结果的解读必须是你自己的。若 AI 生成的代码导致错误结论，按「结果与解读」扣分，不因"是 AI 写的"减免。

## ④ 评分标准

总分 100，折算为课程总成绩的 33%。**评分维度与大纲 §课程评估「期末项目」一致。**

| 评分维度 | 权重 | 评分要点 |
|---|---|---|
| **方案合理性** | 30 | 科学问题明确且可被测序数据回答；样本量与测序量有依据（不是"参考文献都这么做"）；分析线选择与问题匹配；**风险与备选写得具体**（能指出最可能失败的那一步） |
| **结果与解读** | 25 | 结果与方案对应；诊断步骤到位；结论与证据一致；**数据限制如实报告**（样本量不足时按讲义模板报效应量而非硬凑 p 值） |
| **方法选择与结果可信度说明** | 20 | 见下方四问，**评分不看结论对不对，看推理链是否闭合** |
| **可重复性** | 25 | **助教在独立环境执行 `snakemake --use-conda -c 4` 能跑通并渲染出报告**——跑不通此项 0 分；另看 `Snakefile` 无硬编码、`config.yaml` 收纳全部阈值且已版本化、报告尾部有 `sessionInfo()` 与环境快照、README 答得出三个问题 |

### 「方法选择与结果可信度说明」的四个问题

两页之内回答完，每问 5 分。这是契约 `rubric_requirements.method_justification` 的四问在期末项目上的落点（本项目不属 `stats_plugin_topics`，权重按大纲取 20）：

| 要回答的问题 | 期末项目的落点 | 不合格的写法 |
|---|---|---|
| **1. 为什么用这个检验 / 模型？** | 结合**你的数据特点**（计数还是比例、零比例多少、重复数、是否配对）说明方法适配性 | "领域内都这么做" |
| **2. 为什么用这个阈值？** | 至少两个关键阈值，给出依据与**敏感性实测**（换一个值，结论变不变） | "用了默认参数" |
| **3. 假阳性风险在哪？** | 你自己数据里真实存在的混杂（批次、深度、分组不平衡、样本来源）；**这个设计的统计天花板在哪** | "样本量足够" |
| **4. 什么证据能推翻你的结论？** | 你毕业课题里下一步要做的验证实验，以及预期哪个结果最可能不重复 | "需要进一步验证" |

## ⑤ 提交方式与截止

- **提交入口**：课程 LMS「期末项目」；文件名 `学号_姓名_期末项目.zip`（≤ 100 MB——`data/` 与 `results/` 已被 `.gitignore` 排除，超出说明打包方式不对）
- **布置时间**：m08 课上；**截止时间**：m08 课后 **第 21 天 23:59**
- **可重复性验收**：截止后一周内由助教执行；跑不通时会**给一次 48 小时修复窗口**（仅限环境/路径类问题，不接受补交分析内容），修复后通过按该项 80% 计
- **迟交**：3 天内按 90% 计，超过 3 天按 70% 计，超过 7 天不计分（可申请一次不扣分延期，须在截止前提出）
- **重交**：允许在截止前重复提交，以最后一次为准
- **诚信**：方案与解读须独立完成。**同一课题组共用数据必须在方案第 2 节声明**，且方案设计、分析实施与结果解读须各自独立；直接提交他人结果或原样套用配套流程（只改名字）按未完成计
- **数据保密**：涉及未发表数据时，可在提交时申请"仅助教与任课教师可见"，并在 README 注明；**但不接受"因保密而不提交可重复包"**——可用脱敏或微型样例数据满足验收

## ⑥ 常见失分点

按出现频率排序，**前三条都出在「可重复性」这 25 分上**：

| # | 失分点 | 长什么样 | 怎么自查 |
|---|---|---|---|
| 1 | **在自己机器上能跑，在助教那里跑不通** | 硬编码的绝对路径、家目录下的数据库、只在自己环境里装过的包 | 提交前把仓库拷到另一个目录/账号跑一遍；`grep -rn "/home/$USER\|/d3/scratch/$USER" Snakefile scripts/` |
| 2 | **`--use-conda` 首次运行要联网建环境，而计算节点无外网**（m08 ⑨-4） | 集群上报环境创建失败 | 先在登录节点 `snakemake --use-conda --conda-create-envs-only` |
| 3 | **数据没法获取** | `data/` 被 gitignore 了，README 里也没写怎么拿数据 | 公开数据给 `download.sh` + 登录号；私有数据给微型样例 |
| 4 | **方案是结果倒推出来的** | 第 5 节"风险与备选"写不出东西，因为已经知道结果了 | 方案先定稿并 git commit，修订留痕 |
| 5 | **样本量不足却硬报 p 值** | 3 vs 3 写"两组无显著差异"，或反复换方法直到出现显著 | 先按讲义（m06 ⑦-7.5）算最小可能 p 值；不够就报效应量并写清限制 |
| 6 | **阈值散落在 shell 命令里** | `config.yaml` 只有路径，阈值全写死在 `Snakefile` 的 shell 段 | m08 ⑦ 的硬要求：阈值只存 `config.yaml`，且随 git 版本化 |
| 7 | **报告是"死的"** | 改阈值重跑，报告数字没变 | 用 `-P` 传绝对路径；改一个阈值实测一遍 |
| 8 | **三份材料互相对不上** | 方案说要做富集，报告里没有；报告里的图，流程生成不出来 | 提交前对着方案第 4 节逐条核对报告与 `figs/` |
| 9 | **图里出现方块字** | 中文标题在集群 R 环境下渲染为 □□□ | 课程规则：图内一律英文；中文解释写在正文 |
