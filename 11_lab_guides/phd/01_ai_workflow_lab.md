## 2. 实验数据

**本实验没有外部数据，也没有登录号**（`textbook/outline/chapters.yml` 中 ch24 的 `data` 为 `[]`）。全部数据由
`03_code/phd/scripts/01_make_spikein_counts.R` **现场生成**，产物在 `results/p01/` 下：

| 文件 | 形态 | 它是什么 |
|---|---|---|
| `counts.tsv` | 2000 行基因 × 6 列样本（`C1`–`C3`、`T1`–`T3`）+ 表头一行，第一列 `gene_id` | 原始整数 counts，文库大小刻意不等（脚本 L34 的 `lib_factor`，L43 乘进期望值） |
| `coldata.tsv` | `sample`、`condition`、`batch` 三列，6 行 | `condition` 取 `ctrl`/`treat`；`batch` 取 `b1`/`b2`/`b1` 两遍，**与分组交叉、不混杂**（L51） |
| `spikein.txt` | 20 行，每行一个基因名 | 处理组被人为上调 8 倍（$\log_2\mathrm{FC}=3$）的基因清单，即「已知答案」 |

这几行数字都可以**直接读脚本参数区**，不需要跑起来才知道（教材 24.1 与 24.4.5 同口径）：
`set.seed(20260829)`（L19）、`n_gene = 2000`（L25）、`n_each = 3`（L26）、`n_spike = 20`（L27）、
`true_lfc = 3`（L28）、`disp = 0.15`（L29）。

- **固定种子的含义**：`set.seed(20260829)` 保证**全班拿到同一份数据**——你的每个数字都能和同学对，
  **但你的发现路径不能抄**（作业 §③ 的诚信提示与 §⑥ 失分点 1）。
- **已知答案为什么必须在流程之外**：20 个基因名的清单在分析开始之前就写盘，且不经过 DESeq2
  （教材 24.4.5 规则一）。这是三步验证法第 ② 步能执行的前提（失效条件 §24.5.4）。
- **这套数据的限制，先说清**：它是合成矩阵，`disp = 0.15` 是生成器的**设定值**，
  脚本 L29 注释里「真实 RNA-seq 的常见量级」这句话**没有出处**，不要当事实引用
  （教材 24.1、24.4.5）。它没有真实生物学变异与批次效应，只能证明「在这套已知答案上流程的
  响应对不对」，不能替代真实数据验证；迁移到自己的课题时，已知答案要换成经 qPCR 验证的标记基因、
  生物学上应当不显著的管家基因，或已发表的完成图（教材 24.4.5 的三种来源）。
- **工作目录与仓库路径变量**：产物落在工作目录（建议 `/d3/scratch/${USER}/ngs/p01`，不要放家目录）。
  本指导的命令一律用 `${REPO_DIR}` 指向课程仓库根目录，**先定义一次再往下敲**：

  ```bash
  cd /path/to/NGS_3Levels          # 换成你机器上课程仓库的真实根目录（含 03_code/、textbook/）
  export REPO_DIR="$(pwd)"         # 只设一次；换终端要重设
  echo "${REPO_DIR}"               # 打印出绝对路径才算成功
  mkdir -p /d3/scratch/${USER}/ngs/p01 && cd /d3/scratch/${USER}/ngs/p01
  ```

  为什么要它：`<课程仓库路径>` 这类尖括号占位符在 bash 里是**输入重定向运算符**，原样粘贴会报
  `syntax error near unexpected token '<'`，所以命令块里一个不留（`<…>` 只留在模板的填写位）；
  3.1–3.3、3.5、3.6、3.8 都能在工作目录里跑，只有 3.7 的演示要在 `${REPO_DIR}` 下跑。

### 3.1 生成已知答案数据（讲义 ⑤.1）

- **目的**：把「标准答案」在分析之前写盘。没有这一步，第 2 步的回归测试无从执行，
  整条验证链退化成「看起来合理」（教材 24.4.5 规则一、§24.5.4）。
- **命令**（脚本第 1 个实参是输出目录，缺省 `results/p01`，L22）：

  ```bash
  cd /d3/scratch/${USER}/ngs/p01        # §2 已建好；本步之后 3.2–3.3、3.5–3.6 都在这个目录
  Rscript "${REPO_DIR}/03_code/phd/scripts/01_make_spikein_counts.R" results/p01
  ```

- **产出文件**：`results/p01/counts.tsv`、`results/p01/coldata.tsv`、`results/p01/spikein.txt`
  （脚本 L55–59）。stdout 打印三行：`[p01-01] 2000 genes x 6 samples`、spike-in 数与真值、
  六个文库大小。
- **检查点**：
  1. 三件套齐全，`wc -l` 分别为 2001（表头 + 2000 基因）、7（表头 + 6 样本）、20；
  2. `head -2 counts.tsv` 第二行起全是整数，第一列是 `gene_id`；
  3. `cat coldata.tsv` 的 `batch` 列读作 `b1/b2/b1` 两遍——**批次与分组交叉**，不混杂
     （若两组的 batch 完全重合就是混杂，后续 §24.5.3 的「删 batch」陷阱会提前出现）；
  4. `spikein.txt` 里的 20 个名字都能在 `counts.tsv` 第一列找到（`grep -c -F -f` 可核对）。
- **出错信号**：维度不是 `2000 x 6`、counts 含小数、或 `spikein.txt` 不是 20 行 → 生成器被改动，
  **已知答案失效，后面全部作废**，回仓库重新取脚本（教材 §24.5.4：没有已知答案就无法判断对错）。

### 3.2 跑「AI 生成」的差异表达脚本（讲义 ⑤.2）

- **目的**：拿到一个**能跑通、不报错、出图**的分析产物——它本身就是「语法正确但生物学错误」
  的标本（教材 §24.5.1）。本步只负责跑通，不下任何结论。
- **命令**（三个实参：counts、coldata、输出目录；L23–27）：

  ```bash
  Rscript "${REPO_DIR}/03_code/phd/scripts/01_ai_generated_de.R" \
          results/p01/counts.tsv results/p01/coldata.tsv results/p01/ai_out
  ```

- **产出文件**：`results/p01/ai_out/de_results_all.tsv`（全表）、`de_results_sig.tsv`（脚本自己的
  筛选结果）、`dds.rds`（DESeq2 对象，供事后取证）、`volcano.png`、`dispersion.png`（L56–73）。
- **检查点**：
  1. 退出码 0、两张图都生成——**但这不构成通过**（教材 24.5.1 的第一句：退出码只覆盖语法层与运行层）；
  2. `dds.rds` 一定要留着：后面查 `resultsNames()` 与 `sizeFactors()` 全靠它（批处理会话一退出，
  内存里的对象就没了）；
  3. stdout 的 `[p01-02]` 四行摘要先抄进 §4 记录表：检验基因数、差异基因数、`sizeFactors`、
     `resultsNames`（L77–81）；最后一行 `[p01-02] done ->` 只是输出路径（L82），不必抄。
     其中**差异基因数**是这四项里唯一已登记的数：97（`06_data/phd/README.md` p01 节）；
     其余三项是「上机自测，不作判据」。
- **出错信号**：报 `some values in assay are not integers` → 输入不是整数 double，属数据层
  （教材 24.4.6 E1、§24.5.3 的「压制报错」前因）；**若只出现一句 `converting counts to integer mode`
  而不是报错**，说明矩阵「值是整数、存储是双精度」——这句话在这里不是无害提示，按 E2
  「把它当报错看」处理（教材 24.4.4 三态表、24.4.6 E2、§24.5.3）；差异基因数明显不是 97 却又能跑通
  → 先确认自己没改脚本、也没用过别人的 `results/` 目录。

### 3.3 执行三步验证法（本实验核心，讲义 ⑤.3）

- **目的**：用**数值响应**而不是读代码来定位缺陷。三段的能力边界不同（教材 24.4.4 的三步表）：
  ① 查维度与语义、② 查方向与筛选列的数值指纹、③ 查关键中间量。
- **命令**（两个实参：数据目录、AI 输出目录；L19–22）：

  ```bash
  Rscript "${REPO_DIR}/03_code/phd/scripts/01_verify_de.R" results/p01 results/p01/ai_out
  ```

- **产出文件**：`results/p01/ai_out/verify_report.txt`（三段：① 维度与语义自检、② 已知答案的
  回归测试、③ 关键中间量手算复核）。这份报告是作业交付物之一，**原样提交，不许编辑**。
- **运行目录与交付目录是两层，别搞混**：脚本只把报告写进 `ai_out/`，而作业 §② 要的是
  `学号_姓名_p01/results/verify_report.txt`。这两条路径**不是同一层**（运行时的 `results/p01/`
  比交付包里的 `results/` 多一级 `p01`）。所以：

  ```bash
  ls results/p01/ai_out/verify_report.txt     # ① 运行时的那份：脚本产出，原处别删、别改
  #  ② 交付包里的那份：打包时复制（见 3.9），这里只做一遍预演
  mkdir -p stage/results && cp results/p01/ai_out/verify_report.txt stage/results/verify_report.txt
  ```

  同理，3.2 的 `de_results_all.tsv`、3.6 的 `defects_found.tsv`、3.5 的 `refs_check.tsv`
  最终都进交付包的 `results/`；**包里不会出现 `p01/ai_out/` 这一级**，中间产物不必交。
- **检查点**（先自己读报告、写下判断，再翻讲义 ⑥——顺序反了这次作业就白做，作业 §⑥ 失分点 1）：
  1. **① 段的读法**：`counts 维度 2000 x 6` 与 `全为整数 TRUE` 只说明**输入文件本身**是原始
     counts，不说明喂进 DESeq2 的矩阵来源正确（教材 24.4.4 的「查不出什么」栏）。
     `列名与 coldata 对齐 TRUE` 这一行**恒真**：脚本先把 coldata 按 counts 列名重排再比较
     （L39–40），名字集合相同就一定为真，它只能发现缺名/改名，**查不出「同名乱序」**；
     真正的顺序防线在 DESeq2 构建期（同名乱序直接报错）。所以这一行不能当顺序证据。
     **把你自己报告里的四个数抄进 §4**：文库大小 max/min、被验脚本 `sizeFactors` 六个数
     及其 max/min 之比、`design` 字面、`resultsNames` 字面。这四个数都没有登记值，
     全班应当一致（固定种子）但**不作验收判据**。
  2. **size factor 塌在 1.0 附近说明什么（别过度解读）**：原始文库大小明显不等（① 段的 max/min
     远大于 1）而被验脚本的 `sizeFactors` 却挤在 1.0 附近，这是一个**值得追查的线索**，
     不是「归一化做了两次」的证明——同一个指纹也可能来自「输入矩阵已被上游换成 CPM 之类的
     非原始量」或「脚本另做了一次手工缩放」。**要判定成因得凑三样证据**：① 矩阵来源
     （是不是 3.1 生成的 `counts.tsv`，`md5sum` 与同学对）；② 归一化历史（`design(dds)`、
     脚本里有没有先转换再喂进去的动作）；③ 独立对照——把同一份原始 counts 直接交给一个
     **不改矩阵**的参考流程，看它的 `sizeFactors` 散布是否与文库大小差异同量级（3.7 演示的
     A/B 两组就是这个对照的合成版）。三者对齐才能说「多归一化了一次」（教材 24.4.4
     「查不出什么」栏、24.4.5 规则二）。
  3. **② 段的读法（方向）**：两件事不能互相顶替。**绝对方向**看 20 个已知上调基因落在哪一侧
     ——判定线 ≥ 18/20 是**教学约定**（漏检预算 $\lfloor 20\times0.1\rfloor=2$，教材 24.4.4），
     不是通用标准；阳性集换成 $n$ 个就按同一比例重算。**扰动自洽**看互换标签后的镜像相关
     ——它只证明「实现跟着标签重算」，不判绝对方向（教材 24.4.4 第 ② 步、§24.5.4 规则二）。
     课程数据上**已登记**的判据值只有三个：被验脚本上调侧 **0/20**、它与参考流程的
     $\log_2\mathrm{FC}$ 相关 **−0.99**、它的差异基因数 **97**（参考流程 22）
     （`06_data/phd/README.md` p01 节，教材 24.1 与 24.10 同口径）。参考流程自己的召回数与
     镜像相关**没有登记**：这两项写在报告里时要标「上机自测，不作判据」，与 −0.99 分开写，
     它们是**两件不同的事**（教材 24.4.4 第 ② 步末段）。
  4. **③ 段的读法（字面 ≠ 方向）**：`resultsNames` 印着 `condition_treat_vs_ctrl` 是**设计式与
     因子水平**的产物，方向错误藏在 `results()` 调用的 `contrast` 两个元素里（教材 24.4.4 第 ③ 步、
     24.4.6 同理）——所以 ③ 段的正确动作是**回到脚本看一眼 `contrast` 的实参**，不是相信字面。
     BH 一段要分清两种情形：不做独立过滤时手算 $\min_i m p_{(i)}/i$ 与完整 BH 的最小值**严格相等**
     （合成演示 4.116e-07 对 4.116e-07，`textbook/demos/ch24_pvalue_vs_padj.py --selftest` 部分 C，
     「合成算例」）；课程流程做了独立过滤，$m_{\text{eff}}<m$，两个最小值一般不相等——
     报告里写**你自己打印的这两个数**（上机自测，不作判据），只写机制、不写固定倍数
     （教材 24.4.4 第 ③ 步）。
  5. **手算对账**：把 ③ 段打印的「检验基因数 m」代进 $m\times0.05$ 自己算一遍（m 是上机自测值，
     算出来的期望假阳性同样不作判据）；2 万基因档是 $20\,000\times0.05=1\,000$，这个账在
     L0 统计自测里就有（`l0_06_stats` 第 5 题），两档不能混写（教材 24.4.4 硕士选读块）；
     一个基因的 CPM 手算见 3.6。
- **出错信号**：报告缺任一段 → 实参给错（`data_dir` 与 `ai_out_dir` 顺序反了会报找不到文件）；
  三段全绿但 §4 记录表里的数字与讲义 ⑥ 6.1 差很多 → **先怀疑自己动过脚本或数据**，
  用 `md5sum results/p01/counts.tsv` 与同学对；② 段的方向判据异常而 ① 段全绿
  → 正是 §24.5.1 要你学会的形态：维度层看不出方向，必须靠已知答案（教材 §24.5.4）。

### 3.5 文献核查：四步流水线的前三步（讲义 ⑤.5）

- **目的**：把 AI 编造的引用拦在稿件之外。AI 写的 DOI 形状合法、前缀真实，靠肉眼看不出来
  （教材 24.4.7 的三种伪造形态）。
- **命令**（第 1 个实参是 DOI 清单，第 2 个是输出文件名，缺省把清单名的 `.txt` 换成
  `_checked.tsv`，L23–24；`refs.txt` 放在你自己的工作目录里）：

  ```bash
  printf '%s\n' \
    10.1186/s13059-014-0550-8 \
    10.1038/s41586-023-99999-9 \
    > refs.txt                      # 第一条是真 DOI，第二条是练习用的伪造 DOI，见下
  mkdir -p stage/results
  bash "${REPO_DIR}/03_code/phd/scripts/01_check_refs.sh" refs.txt stage/results/refs_check.tsv
  #   ↑ 第 2 个实参就是输出文件名，直接写成作业要的名字，不用事后改名/搬文件
  ```

  第 2 个实参可省（L23–24 的 `[outfile]`）；省掉时输出名是清单名的 `.txt` 换成 `_checked.tsv`
  （`refs_checked.tsv`），你还得自己改名搬位置——**所以直接给它**。先写进 `stage/results/`
  （3.9 的打包暂存区），打包时整个 `stage/` 就成了交付包结构。
  两条 DOI 不是随便写的：第一条（DESeq2 原文，Genome Biology 2014）确认「真 DOI 走完全绿通道」；
  第二条**故意造**成形状合法、前缀真实却注册不到的样子（`99999-9` 是占位，不是任何真实论文），
  专把 404 分支跑出来。**第二条永远不许出现在你的报告或引用里**——它只是演练靶子。
  练完就用 AI 生成的 5 条替换整个 `refs.txt`。

  **这条为什么不在计算节点跑**：脚本要访问 doi.org / api.crossref.org / eutils.ncbi.nlm.nih.gov，
  计算节点不通外网（根 `CLAUDE.md` 集群事实），投递出去只会得到整表 `UNCERTAIN_http_000`。
  文献核查是本实验**唯一需要外网的步骤**，也是唯一只能在登录节点直接跑的一步。
  脚本 L21 也会激活环境（见 §1）；每条 `sleep 1`（L106）对公开 API 保持礼貌，耗时随 DOI 条数
  线性增长；单条 `curl` 封顶：doi.org 20 秒（L38），Crossref / DataCite / PubMed 各 25 秒
  （L41、L59、L81）。
- **产出文件**：`stage/results/refs_check.tsv`，**7 列**：`doi`、`http_status`、`title`、
  `container_or_publisher`、`year`、`pubmed_hits`、`verdict`（脚本 L27 的表头就是这 7 个，
  **以脚本表头为准**，作业 §② 的 `DOI | HTTP 状态 | 标题 | 期刊 年份` 是简写）。
- **检查点**：
  1. 首行是上面 7 个列名（不是 4 列或 6 列——列数不对说明你拿到的是旧版/改过的脚本）；
  2. DOI 解析的判据是**期望 301/302/303**；`404` 只说明这一次没解析到，可能没注册，
     也可能抄错、代理或服务异常——`FAKE_or_UNRESOLVABLE` 是**待复核标签，不是伪造的认定**
     （教材 24.4.7 第 ① 步）；
  3. `verdict` 按现状有五态外加一个撤稿标签：`FAKE_or_UNRESOLVABLE`、
     `RESOLVES_crossref_check_abstract_manually`、`RESOLVES_datacite_check_abstract_manually`、
     `RESOLVES_no_metadata_check_manually`、`UNCERTAIN_http_*`，以及
     **`RETRACTED_do_not_cite`**（撤稿论文的 DOI 照样解析 302，脚本只能靠**题名前缀**
     标记，L95–97 匹配题名开头的 `RETRACTED`/`WITHDRAWN`）。**能力与边界都要记准**：
     ① 它抓的只是「出版方把 `RETRACTED:` 写进题名」这一种形态，是撤稿核查的**一部分**；
     ② **没有这个标签 ≠ 没被撤稿**——撤稿通知常以独立短文发布、原题名不变，勘误与
     关注声明更是从不改题名，这类只能人工看出版方页面与注册机构的关联更新
     （Crossref `updated-by` / PubMed `Retraction of`）；③ 所以流程是「脚本标红 → 换文献；
     没标 → 人工抽查你真正要引的那几条并在报告里写清查了什么」（教材 24.4.7 后半段）。
     注：教材 24.4.7 与 §24.5.2 的这一处叙述早于脚本这道判定；若你手上的教材仍写着「脚本
     不识别撤稿」，以你实跑的 `verdict` 列为准，并在报告里注明这处不一致。
  4. 两条边界要记：arXiv 一类 **DataCite 注册**的 DOI 在 Crossref 无题录属正常（脚本 L58–76
     会回退查 DataCite），**不是伪造**；非 MEDLINE 期刊的 `pubmed_hits` 天然为 0，也不是伪造
     （教材 24.4.7）；
  5. 第 ④ 步没有脚本：**打开摘要确认原文真的说过你要引用的那句话**。前三步全绿仍可能是
     「张冠李戴」，这一类只有人读摘要能抓（教材 24.4.7、§24.5.2）。
- **出错信号**：全表 `UNCERTAIN_http_000` → 网络或代理问题（或你在计算节点上跑），
  **不是文献全假**；`RESOLVES_*` 就写「文献全部真实」→ 恰好漏掉最隐蔽的一类（教材 §24.5.2）；
  看到 404 就去「把 DOI 修对」→ 越修越错，标题通常也是编的（教材 24.4.6 E8）。

### 3.6 手算复核与缺陷定位表（讲义 ⑥ 的落点）

- **目的**：把 3.3 打印出来的中间量自己算一遍，并为每一处缺陷写一条「30 秒内可被第三方复现」
  的一行验证命令（作业 §③ 第 4 条）。这一步的产出是作业里最难伪造的一栏。
- **命令**：无新脚本。三笔账都在 R 里算，算式写进报告。**本步同样是计算**，按纪律投计算节点：

  ```bash
  cat > hand_calc.R <<'EOF'
  args <- commandArgs(trailingOnly = TRUE)
  m   <- as.numeric(args[1])   # 报告里的「检验基因数」
  cnt <- as.numeric(args[2])   # 你点名的那个基因在样本 1 的 counts
  lib <- as.numeric(args[3])   # 该样本的文库大小（① 段逐个印出）
  m * 0.05                                             # ① 期望假阳性
  20000 * 0.05                                         # ① 2 万基因档的账
  cnt / lib * 1e6                                      # ② CPM 手算
  res <- read.delim("results/p01/ai_out/de_results_all.tsv")
  n <- sum(!is.na(res$pvalue))
  min(sort(res$pvalue) * n / seq_len(n), na.rm = TRUE) # ③ BH 手算式
  min(res$padj, na.rm = TRUE)                          # ③ 完整 BH 的最小值
  sum(is.na(res$padj))                                 # ③ NA 行数，先数再用
  EOF
  export M=… CNT=… LIB=…          # 三个数抄自你自己 3.3 的报告，不抄同学、不抄本指导
  Rscript hand_calc.R "$M" "$CNT" "$LIB"
  ```

  集群上把这行包进作业脚本投递（写法同 3.8）；本地跑就在报告里注明「本地运行」。
  ② 的闭式公式可用合成演示对一遍：`textbook/demos/ch24_double_normalization_sizefactors.py
  --selftest` 部分 C 打印「counts=20、文库=318555 → CPM 62.78」——**合成算例**的输入，
  不是课程数据；用它确认算式与闭式公式一致，再代入你自己的两个数。
- **产出文件**：`defects_found.tsv`（作业 §② 的缺陷定位表，打包后位于交付包的 `results/` 下，
  五列：行号｜类型｜指纹｜发现路径｜一行验证命令）。**行号指你自己在脚本里定位到的位置**，
  本指导不提供。首行表头照抄下面这一行（中文表头、制表符分隔，助教按字段位置读）：

  ```bash
  printf '行号\t类型\t指纹\t发现路径\t一行验证命令\n' > defects_found.tsv
  printf '%s\t%s\t%s\t%s\t%s\n' \
    "N" "五类错误之一（见教材 24.4.2 表）" \
    "我在报告里先看到的那个异常数字（一句话）" "② 段 / ③ 段 / 哪一步、看到什么才起疑" \
    "一条能在 30 秒内复现该判断的命令" >> defects_found.tsv   # ← 整行是格式示范，五格都要换成你的
  ```
- **检查点**：
  1. 三笔账都能在报告里重算：$97/22\approx4.4$（已登记的两个差异基因数之比，倍数不固定，
     教材 24.4.4）、$20\,000\times0.05=1\,000$。你的 $m\times0.05$ 与你的 CPM 都是**上机自测值**，
     报告里带上你代进去的两个原始数（m、counts 与文库大小），让别人能复算即可，不必与同学相同口径
     之外的固定值对齐；
  2. 「发现路径」一列写的是**你先看到哪个数字**才起疑（差异基因数跳到 100 上下？spike-in 全在
     下调侧？size factor 挤在 1.0 附近？），不是「读代码看出来的」，更不是「讲义或他人说有几处」——
     后者按作业 §⑥ 失分点 1 直接判失分；
  3. 表头逐字与上面一致（五个字段、制表符分隔、无多余空格）；每行五个字段都非空；
  4. 每条「一行验证命令」都能在 30 秒内让同学复现你的判断。注意 R 的干净会话里
     **`resultsNames()` 必须先 `library(DESeq2)`**（否则报 `could not find function`），
     所以写成 `Rscript -e 'library(DESeq2); dds <- readRDS("results/p01/ai_out/dds.rds");
     print(resultsNames(dds)); print(sizeFactors(dds))'`，再打开脚本核对 `contrast` 实参
     （教材 24.4.4 第 ③ 步；`01_verify_de.R` 自己在 L16 也是先 `library(DESeq2)`）。
- **出错信号**：`defects_found.tsv` 里「类型」一栏全写成「逻辑错误」→ 五类错误的分类在教材
  24.4.2 的表里，逐条对；发现路径写成「仔细阅读代码发现」→ 作业 §⑥ 失分点 2 的原文描述，
  也正好是教材 §24.5.1 要求你别接受的那种证据（能跑通 ≠ 已验证，必须落到某个数字上）；
  取子集时 `padj` 的 NA 让你算错行数 → 先 `sum(is.na(res$padj))` 数一遍再筛
  （教材 24.4.6 E6；`filter` 会静默丢 NA，你必须**知道**它丢了多少行）；
  `could not find function "resultsNames"` → 少写了 `library(DESeq2)`，不是 dds 坏了。

### 3.8 集群提交：一条命令跑完 3.1–3.3（主路径，**集群未实测**）

- **目的**：这是**集群环境下的主路径**。3.1–3.3 三条命令手动敲容易漏步、也容易在登录节点上跑
  （根 `CLAUDE.md` 的纪律）。`01_run_ai_practice.sh` 把三步串成一次作业提交，日志本身就是
  「三步都跑过」的凭证。
- **命令**（产物目录用 `-v` 显式传给作业；`qsub` 与脚本都用带引号的绝对路径）：

  ```bash
  cd /d3/scratch/${USER}/ngs/p01                 # 提交目录（-cwd 让作业在此运行）
  OUT="/d3/scratch/${USER}/ngs/p01/results/p01"  # 产物目录，写绝对路径
  qsub -v OUTDIR="${OUT}" "${REPO_DIR}/03_code/phd/scripts/01_run_ai_practice.sh"
  qstat -u "$USER"                                # 看排队/运行状态
  # 没有 SGE 的个人机器（不是集群）才走这条，报告里注明「本地运行」：
  # OUTDIR="${OUT}" bash "${REPO_DIR}/03_code/phd/scripts/01_run_ai_practice.sh"
  ```

  **为什么必须写成 `-v`**：`OUTDIR="${OUT}" qsub ...` 只给 `qsub` 命令自身设了个环境变量，
  `qsub` 不转交给作业——脚本作业头（L2–7）也**没有** `-V`/`-v`，作业进程拿到的 `OUTDIR` 是空的，
  脚本 L28 于是退回缺省 `results/p01`（相对 `-cwd` 的提交目录）。语法是 `qsub -v NAME=value`，
  多个用 `-v A=1,B=2`；值里有空格或中文要整体加引号。脚本内部（L28/L29/L27/L21/L22、
  三步调用 L33/36/40）见 §8 指针，三个 `Rscript` 都拼 `${SCRIPT_DIR}`，**不依赖当前目录**。
- **产出文件**：SGE 作业日志（作业名 `p01_ai_practice`（L3）、`-j y` 把 stdout/stderr 合进一个
  日志（L5），落在提交目录下 `<作业名>.o<作业号>`）＋ `results/p01/`、`results/p01/ai_out/`，
  与 3.1–3.3 的产物同名同结构。
- **检查点**：
  1. **产物落在你指定的目录**：`ls "${OUT}/ai_out/de_results_all.tsv"` 能列出来。若发现产物跑到了
     提交目录下的 `results/p01/`（而不是 `${OUT}`），说明 `-v` 没生效或参数写错——这是本步最容易
     失败的环节。日志里可交叉验证：三步脚本的结束行都写在同一个 `OUTDIR` 前缀下；
  2. 日志开头的 `[host]` 行（脚本 L24）打印的**不是**登录节点主机名——这就是「确实在计算节点上跑」
     的证据（`l0_01_linux` 的 `L0-1-Q9` 同一个判据）。本地跑时它是本机名，属正常，但**不能**
     当作集群已跑过的证据（§4 记录表为此给了两套填法）；
  3. 三步标题依次出现：`=== [1/3] 生成已知答案数据 ===`（L32）、`=== [2/3] 运行 AI 生成的
     差异表达脚本（含教师植入错误） ===`（L35）、`=== [3/3] 三步验证法 ===`（L39）；
  4. 日志里能看到三步脚本各自的结束行：`[p01-01]` 三行（生成器 L61–63）、`[p01-02]` 摘要四行
     ＋`done ->` 一行（被验脚本 L77–82）、`[p01-03] 报告已写入:` 一行（验证脚本 L108），
     并且 `${OUT}/ai_out/verify_report.txt` 生成。
- **出错信号**：日志首行 `Rscript: command not found` → 作业没继承登录环境，脚本 L22 的
  `source ... activate ngs_phd_base` 那条没生效（教材 24.4.6 E7、⑨-E7）；`[host]` 与登录节点
  相同 → 你在登录节点直接 `bash` 跑了（数据小，本地跑本身允许，但日志不能当「集群跑过」的证据）；
  产物目录不对 → 先查 `qsub -v` 的拼写与引号（见上）；作业被 `qdel`/超时 → 先看 `qstat` 与
  日志末行，别默认脚本有问题。
- **未实测声明**：本机 `command -v qsub` 无输出（无 SGE），**本步只在本地 `bash` 路径上验证过
  脚本可读（`bash -n` 通过）**；`qsub -v` 的变量传递、`qstat` 输出、日志文件名格式均**未实测**。
  你在集群上第一次跑时，以日志真实输出为准，不要照抄任何「预期主机名」或「预期日志名」。

## 5. 失效条件对照（教材 §24.5，本实验里在哪一步、看什么能察觉）

1. **语法正确但生物学错误是常态：能跑通不构成验证**（§24.5.1，机制 §24.4.1–§24.4.2）｜3.2–3.3：
   现场就在 3.2——脚本退出码 0、两图生成、结果表列名齐全，`resultsNames()` 字面也对，
   差异基因数却从 22 抬到 97、20 个已知上调基因全部落在下调侧（README p01 节）。
   **察觉**：不接受「退出码 0」当证据；每个要写进论文的数字都要有可执行判据；
   看三个低成本信号（$m\times0.05$ 的账、阳性基因落在哪一侧、`sizeFactors` 是否挤在 1.0 附近
   而原始文库仍有明显差异），任一异常就转 ② 段，不要靠读代码找答案。
2. **AI 编造的引用形状合法，只能逐字段实查发现**（§24.5.2，机制 §24.4.7）｜3.5：
   DOI 形状合法、前缀真实却解析 404；或 DOI 能解析、题录逐字正确、PubMed 也查得到，
   却被用在它不支持的论断上——前三步全绿，错误进了正文。
   **察觉**：四步逐条走；记三条边界（DataCite 系预印本 Crossref 无题录不等于假、非 MEDLINE
   期刊 PubMed 命中数为 0 不等于假、**撤稿文献的 DOI 照样解析 302，脚本只能靠题名前缀抓到
   其中一部分**）；`RETRACTED_do_not_cite` 见到就换文献；**没有这个标签不等于没被撤稿**，
   你真正要引的那几条必须人工看出版方页面与注册机构的关联更新（见 3.5 检查点 3）。
3. **「修复」建议压制报错，把显性错误变成静默错误**（§24.5.3，机制 §24.4.6）｜3.1–3.2：
   3.1 产出的是**原始整数 counts**（本该直接喂进来的那份输入），而 3.2 的脚本给出的现象是
   **不报 E1 那种「这不是 counts」的错，只留一句 `converting counts to integer mode`，
   同时 `sizeFactors` 挤在 1.0 附近**——这正是「某一层替你把输入改写了、于是报错不再触发」的
   通用形态（教材 §24.5.3 的判据句）。**具体是哪一个动作改写了输入、改在哪一行，
   本指导不说**：你要自己从 ①②③ 三段的数字倒推，并用 3.7 的合成演示校准「改写之后指纹
   应该长什么样」（对照：同演示 B 组那套被改写过输入的矩阵，文库 max/min 被拉到 1.0001、
   size factor 散布从 2.38× 塌到 1.03×，均为**合成算例**；改写前形态见同演示 A 组）。
   **察觉**：拿到补丁先问「它改变了哪个数字的含义」；对 `round()`/`na.omit()` 先数 NA 的
   数量与位置；对删协变量先画按批次着色的 PCA；对「关掉报错」加主动拦截
   （`stopifnot(all(cts %% 1 == 0))`），拦截写在分析之前。
4. **没有已知答案就无法判断对错：须先造 spike-in 式的已知答案数据**（§24.5.4，机制 §24.4.5）｜3.1：
   本实验的第一件事就是把答案写盘；跳过 3.1 直接跑 3.2，你拿到的 97 与 0/20 只是两个数，
   无法判断谁对。
   **察觉**：开工前问三个问题——阳性对照是什么、阴性对照是什么、两个答案是不是在流程之外
   生成的（本实验：20 个基因名写在 `spikein.txt`，不经过 DESeq2）；三条规则各对一条判据
   （答案独立＝先写盘再跑；扰动与错误模式对偶＝抓方向用阳性落位＋显式 `contrast`，
   抓「没按标签重算」才用互换标签；阳配阴＝同时报「找回多少」与「混进多少」）。

   （§24.7 习题 8，开放题）
