## 0. 本实验对应什么

- **学时**：u03 为 4 学时线上自学单元；本实验是其上机部分，产出直接服务 u08 综合项目
  报告的「数据量和质量评估」一节（《学生实验操作手册》报告模板 §2.3）。

  bash/awk/zcat；samtools（pin 1.17）只用于步骤 7 的 FLAG 练习。
- **计算纪律**：交互查看（`ls`/`file`/`head`/`od`/`grep`）、合成小文件演算与 demo

  步骤 5 想看真实数据分布时的解码（脚本会完整扫一遍输入并排序算 N50，不是

  也只在登录节点做。

### 步骤 0：环境与脚本冒烟

- **目的**：确认环境激活、脚本在位、语法完好，用一个 3 条序列的合成小样例跑通全链路。
- **命令**（登录节点）：

  ```bash
  mkdir -p /d3/scratch/${USER}/ngs/u03 && cd /d3/scratch/${USER}/ngs/u03   # 校外个人机器：~/ngs/u03
  source /opt/miniconda3/bin/activate && conda activate ngs_ug_base   # 校外：source 路径按实际替换（§1）
  ls <课程仓库路径>/03_code/undergraduate/scripts/03_parse_fastq_stats.sh
  bash -n <课程仓库路径>/03_code/undergraduate/scripts/03_parse_fastq_stats.sh
  printf '>r1\nACGTACGTACGT\n>r2\nTTTTAAAACCCC\n>r3\nGGGG\n' > smoke.fa
  bash <课程仓库路径>/03_code/undergraduate/scripts/03_parse_fastq_stats.sh smoke.fa 4m 0
  ```

  这条命令在做什么：`bash -n` 只做语法检查（无输出即通过）；冒烟样例用 3 条合成
  FASTA 验证「识别格式 → 统计 → 估算深度」全链路。脚本三个参数依次是**序列文件、
  基因组大小（支持 4m/4M/4000000 写法）、FASTQ 解码条数**（0 = 不解码；FASTA 输入
  本也不解码）。
- **产出**：`smoke.fa`（3 条合成序列的冒烟样例，用完可直接丢弃）＋终端输出。
- **检查点**：脚本路径打印存在；`bash -n` 无输出；冒烟输出含七个统计字段
  （序列条数 / 碱基总量 / 最短最长 / 平均 / 中位 / N50 / 估算深度），尾行提示把
  四个数抄进报告模板 §2.3。深度一栏显示 `0.0 X` 是**舍入的正常现象**：冒烟样例
  共 12+12+4 = 28 bp，28 ÷ 4,000,000 = 7×10⁻⁶，按一位小数打印就是 `0.0 X`——
  不是数据被清空，也不是计算出错。
- **出错信号**：`conda: command not found` → 回 §1 修环境；`[ERROR] 文件不存在：…`
  （rc=2）→ 路径打错，先 `ls` 核对；冒烟就语法报错 → 你改动过脚本或拷错版本，从课程
  目录重新复制（课程公共目录只读，个人改动走自己的副本）。

- **产出**：文件清单。
- **检查点**：校内能看到 `reads.fa`；校外 `ERR15732384_ont.fastq.gz` 下载大小

### 步骤 2：三道排查——文件是什么（只读，登录节点）

- **目的**：不看扩展名，用物理指纹回答「压缩了吗、什么语法格式」，即教材 §5.4.1
  三层判别（物理编码 → 语法 → 生物学身份）的前两层。
- **命令**（按轨道二选一；先看魔数再决定怎么取首行）：

  ```bash
  # ── 校内轨道：F 是纯文本 FASTA ──
  F=/data/lab/ngs/reads.fa
  file "$F"
  head -c 2 "$F" | od -An -tx1        # 期望：不是 1f 8b
  head -1 "$F"                        # 期望：首字符 >
  # ── 校外轨道：F 是 gzip 压缩流 ──
  F=${DATA}/reads/ERR15732384_ont.fastq.gz
  file "$F"
  head -c 2 "$F" | od -An -tx1        # 期望：1f 8b（gzip 魔数）
  zcat "$F" | head -1                 # 解压后取首行；直接 head -1 会把二进制乱码打进终端
  ```

  这条命令在做什么：`file` 看系统级类型；`head -c 2 | od -An -tx1` 取开头两个字节的
  十六进制——gzip 流的魔数是 `1f 8b`；**先判魔数再取首行**：纯文本直接 `head -1`，
  gzip 必须 `zcat` 解压后看（否则乱码上屏、看不到 `@`）。脚本内部用同一判据：按
  魔数选读取器（zcat/cat）、按首字符判格式。
- **产出**：终端几行输出。
- **检查点**：校内 `reads.fa`：`file` 报文本、首两字节**不是** `1f 8b`、首字符是 `>`
  （它是被剥掉质量值的长读段 FASTA，不是参考基因组——教材 §5.4.1 的「常见误用」）；
  校外 `ERR15732384_ont.fastq.gz`：`file` 报 gzip、首两字节 `1f 8b`、**解压后**
  首字符 `@`。首字符只是格式**线索**，不是完整判据——最终靠脚本逐条结构校验与
  md5 对账（步骤 4/6）。
- **出错信号**：扩展名 `.gz` 而前两字节不是 `1f 8b` = 假压缩（或截断只剩好头）；
  扩展名 `.fa` 而前两字节是 `1f 8b` = 伪装扩展名。都回步骤 1 重验（教材 §5.5.4）。
  脚本对假 gz 按纯文本读、不报错——这一步要靠人看。前两字节不是 `1f 8b` 也
  不等于「一定是纯文本」（还可能是别的压缩或二进制），`file` 与首字符对不上时
  先停下来确认文件来源。`zcat` 自身报错 = 压缩层损坏，重传。首字符既非 `>` 也
  非 `@` → 不是 FASTA/FASTQ，脚本以 rc=3 退出。

### 步骤 3：`@` 计数陷阱（合成演示，登录节点）

- **目的**：亲眼看「行首 `@` 计数」为什么会多算，建立「双口径对账」习惯
  （教材 §5.5.2）。
- **命令**：

  ```bash
  cd /d3/scratch/${USER}/ngs/u03      # 校外个人机器：~/ngs/u03（或任何可写目录）
  printf '@R1\nACGT\n+\nIIII\n@R2\nTTTT\n+\n@III\n' > trap.fq
  cat -A trap.fq                          # 先看清楚这 8 行里有什么
  grep -c '^@' trap.fq                    # 错误做法
  wc -l < trap.fq | awk '{print $1/4}'    # 正确做法：行数 ÷ 4
  # 合成算例复核（绝对路径，任意当前目录可跑）：
  PYTHONDONTWRITEBYTECODE=1 python3 <课程仓库路径>/textbook/demos/ch05_phred_fastq.py --selftest
  ```

  这条命令在做什么：手工构造 8 行 FASTQ（2 条记录），第 2 条的质量行故意以 `@` 开头；
  两种数法对照。demo 用同构输入把整条算术链（8 行、grep=3、÷4=2、`@`=ASCII 64
  = Q31 = 7.94×10⁻⁴）现跑一遍。
- **产出**：两个计数 + demo 的 SELFTEST 输出。
- **检查点**：`grep -c '^@'` 得 **3**，`行数 ÷ 4` 得 **2**（demo 现跑锚点，
  2026-11-10 本机 PASS）。多出来的 `@` 是质量行的行首：`@` 是合法质量字符
  （ASCII 64 − 33 = Q31，判错概率 7.94×10⁻⁴），不是脏数据。
- **出错信号**：两口径差 1 以上 → 先怀疑**数法**（质量行首 `@`、折行、提供方计数
  口径），不是数据坏；确认就逐块看结构（每块 `@`/`+`/等长，教材 §5.5.2）。
  FASTA 用 `grep -c '^>'`，两种格式的数法别混用——质量行同样可能以 `>` 开头。

### 步骤 4：主统计——四指标（真实数据，走 qsub）

- **目的**：对真实数据跑宏观体检，产出报告的四个数字：序列条数、碱基总量、
  读段 N50、名义深度。
- **命令**（校内轨道：登录节点写作业脚本后投递；校外自学在个人机器上直接跑
  第二条命令）：

  ```bash
  cd /d3/scratch/${USER}/ngs/u03      # 校外个人机器：~/ngs/u03（无 qsub，见第二条命令）
  # ① 先把课程仓库路径存进变量 REPO。尖括号占位符绝不能留在作业脚本里——
  #    带引号的 heredoc 不会展开它，SGE 运行时会拿 < 当重定向符直接报错：
  REPO=<课程仓库路径>
  cat > u03_stats.job <<EOF
  #!/bin/bash
  #$ -S /bin/bash
  #$ -N u03_stats
  #$ -cwd
  #$ -j y
  #$ -pe smp 1
  source /opt/miniconda3/bin/activate
  conda activate ngs_ug_base
  bash ${REPO}/03_code/undergraduate/scripts/03_parse_fastq_stats.sh \
      /data/lab/ngs/reads.fa 4m 0 > stats_reads_fa.txt 2>&1
  EOF
  # ② 投递前检查：作业脚本里不应再出现「课程仓库路径」字样：
  grep -n '课程仓库路径' u03_stats.job && echo "还有占位符未替换，先改再投" || echo "作业脚本就绪"
  qsub u03_stats.job
  qstat -u ${USER}          # qw 排队 / r 运行 / Eqw 报错
  # 作业结束后（u03_stats.o<作业号> 是作业日志，stats_reads_fa.txt 是脚本输出）：
  cat stats_reads_fa.txt
  ```

  ```bash
  # 校外轨道（个人机器直跑，无 qsub；参数 2 用完成图全长作分母，参数 3 保留解码供步骤 5；
  # tee 同时落盘一份原始输出，供 §7 打包提交）
  bash <课程仓库路径>/03_code/undergraduate/scripts/03_parse_fastq_stats.sh \
      "${DATA}/reads/ERR15732384_ont.fastq.gz" 4768212 2 | tee stats_ERR15732384.txt
  ```

  这条命令在做什么：作业头五个指令与课程其他作业脚本同口径（`-cwd` 让日志落在
  投递目录）；第 ① 步用不带引号的 `<<EOF`，`${REPO}` 在写文件时就被展开成真实
  路径（`${USER}` 同理）。脚本一遍读完输入：按魔数判压缩、按首字符判格式；FASTQ

### 步骤 5：FASTQ 质量字符解码（合成样例在登录节点；真实数据走 qsub）

- **目的**：把第 4 行质量字符逐位还原成 Q 值与判错概率，确认「手算 = 脚本打印」
  （教材 §5.4.3）。校内 FASTA 没有质量行可解，本步用合成样例入门、校外 ONT
  FASTQ 看真实分布。
- **命令**：

  ```bash
  cd /d3/scratch/${USER}/ngs/u03      # 校外个人机器：~/ngs/u03
  # 合成小样例（10 bp：脚本只打印每条前 10 位，长度刚好够全表手算）：
  printf '@R1\nACGTACGTAC\n+\nFFFFFFFFFF\n@R2\nTTTTAAAAAA\n+\n::::::::::\n' > decode.fq
  bash <课程仓库路径>/03_code/undergraduate/scripts/03_parse_fastq_stats.sh decode.fq 4m 2
  # 换算表锚点复核（绝对路径，任意当前目录可跑）：
  PYTHONDONTWRITEBYTECODE=1 python3 <课程仓库路径>/textbook/demos/ch04_phred_q.py --selftest
  ```

  想看真实数据时：命令同上，输入换成 `"${DATA}/reads/ERR15732384_ont.fastq.gz"`、
  分母 `4768212`、解码条数 2。**校内集群把它放进作业再投**（脚本会完整扫一遍输入、
  排序算 N50，是计算不是交互查看；把步骤 4 作业模板第 ① 步里的统计命令换成这条、
  输出重定向到 `stats_ERR15732384.txt` 即可）；校外个人机器直接跑。这条命令在做
  什么：脚本对前 N 条 FASTQ 逐字符做「ASCII − 33 = Q、P = 10^(−Q/10)」，打印
  pos/base/qchar/ASCII/Q/P 六列与该条平均 Q。
- **产出**：解码表 + demo 输出。
- **检查点**：
  1. 手算与打印逐位一致：任取一位，ASCII − 33 得 Q，10^(−Q/10) 得 P，对照打印行。
     合成锚点（2026-11-10 本机现跑）：`F` = 70 → Q37 → 0.00020；`:` = 58 →
     Q25 → 0.00316。
  2. demo 表 1 锚点：`!`→Q0→P=1；`#`→Q2→0.631；`5`→Q20→0.01；`?`→Q30→0.001；
     `I`→Q40→0.0001。这些是换算结果，不是合格线（教材 §5.4.3）。
  3. 真实数据上质量沿位置变化（Illumina 的 3′ 端下降、ONT 的同聚物区，是两种不同
     机制，教材 §4.5.1/§4.5.2）。本步只看每条前 10 位；完整位置曲线归 u04（FastQC）。
- **出错信号**：手算与打印对不上 → 先查自己的 ASCII 表（`F` 是 70 不是 40）和
  指数按法；确认无误再怀疑脚本。看到大片 `!`/`#`（低 Q 字符）**支持**真实质量差
  的可能，但先确认两件事再下结论：编码口径（你手上的 ASCII−33 换算与脚本一致）
  与数据来源（这批数据本身的判读质量）；分层对照前不写成排他诊断（教材 §5.4.3
  与 §4.5.1 的分层排查口径）。

### 步骤 6：负例三连——失效条件现场（合成小文件，登录节点）

- **目的**：亲手验证「检查通过 ≠ 文件完好」：同一个脚本，三种损坏三种命运
  （教材 §5.5.4）。
- **命令**：

  ```bash
  cd /d3/scratch/${USER}/ngs/u03      # 校外个人机器：~/ngs/u03
  # ① 尾部截断：最后一条记录缺质量行（共 7 行）
  printf '@r1\nACGT\n+\nIIII\n@r2\nACGT\n+\n' > bad_trunc.fq
  # ② 序列与质量不等长（4 bp 对 3 字符）
  printf '@r1\nACGT\n+\nIII\n' > bad_len.fq
  # ③ 中部缺行 + 人工凑整：第 2 块的序列与质量其实来自另一条记录，结构全合法
  #    （质量行必须 33 字符、与第 6 行序列等长——多打一个字符它就会被逐条校验拦下，
  #     演示不出「静默放行」）
  cat > bad_mid.fq <<'EOF'
  @READ_0001
  GATCGGAAGAGCACACGTCTGAACTCCAGTCAC
  +
  FFFFFF:FFFFFFFFF,FFFF#FFFFFFFFFFF
  @READ_0002
  CCGTAGGCATGCTAGCTAGGATCCGATGCAATG
  +
  IIIIIIIIIIIIIIIIII?IIIIIIIIIIIIII
  EOF
  for f in bad_trunc.fq bad_len.fq bad_mid.fq; do
    echo "== $f =="
    bash <课程仓库路径>/03_code/undergraduate/scripts/03_parse_fastq_stats.sh "$f" 4m 0
    echo "rc=$?"
  done
  # 程序化对照（绝对路径，任意当前目录可跑；其算例 3(b) 与本步 ③ 同构）：
  PYTHONDONTWRITEBYTECODE=1 python3 <课程仓库路径>/textbook/demos/ch05_phred_fastq.py --selftest
  ```

  这条命令在做什么：① 拦得住——总行数 7 不整除 4；② 也拦得住——逐条校验发现
  质量比序列短；③ 拦不住——传输出错后有人手工删行凑回 8 行，第 2 块的序列/质量
  来自另一条记录，但长度相等、`@`/`+` 都在，脚本照常统计、照常打印「完成」。
- **产出**：终端输出（三份 stdout/stderr 与退出码，命令本身不落盘）。退出码随手
  记进 §4 表；需要留档时把 for 循环整体输出 `| tee bad_cases.log`，把 `bad_*.fq`
  三个输入文件与日志一起放进 §7 压缩包。
- **检查点**（2026-11-10 本机现跑锚点）：① → `[ERROR] FASTQ 损坏：总行数 7 不是 4
  的整数倍`，**rc=5**；② → `[ERROR] FASTQ 损坏：第 4 行质量长度 3 ≠ 序列长度 4`，
  **rc=5**；③ → 统计出 2 条、66 bp、打印「完成」，**rc=0**（静默放行）。
  demo 算例 3(b) 把 ③ 的构造与放行结果现跑复核（PASS）。
- **出错信号**：以为 ③ 该报错而它没有——这正是教材 §5.5.4 要教的事：「完成」只
  表示统计跑完，不表示文件完好。处置是 md5 对账＋提供方条数核对＋重传；删行凑整
  是把显性截断变成静默错配，绝对禁止。

### 步骤 7：FLAG、CIGAR 与坐标三件套（登录节点即可）

- **目的**：三个「不报错」家族的手算锚点：FLAG 位拆解、CIGAR 消耗对账、BED/GFF
  坐标换算（教材 §5.4.5 / §5.4.6 / §5.4.4）。
- **命令**：

  ```bash
  samtools flags 163
  # 合成锚点复核（绝对路径，任意当前目录可跑）：
  PYTHONDONTWRITEBYTECODE=1 python3 <课程仓库路径>/textbook/demos/ch05_flag_cigar.py --selftest
  PYTHONDONTWRITEBYTECODE=1 python3 <课程仓库路径>/textbook/demos/ch05_bed_gff_coords.py --selftest
  ```

  这条命令在做什么：`samtools flags` 把整数翻译成置位列表；两个 demo 把三组固定
  算例（无随机数）现跑：FLAG 位拆解、CIGAR 查询/参考消耗、双坐标系换算。
- **产出**：终端输出。
- **检查点**（全部 2026-11-10 本机现跑 PASS）：
  1. `samtools flags 163` → `0xa3 163 PAIRED,PROPER_PAIR,MREVERSE,READ2`；手算
     163 = 128 + 32 + 2 + 1（R2、配对端在负链、proper pair、双端文库），16 位未
     置位 = 自身在正链。对照值 99 / 83 / 147 同样可拆（demo 算例 1）。注意
     proper pair 只是比对器的几何判定，不保证没有错配（教材 §5.4.5）。
  2. CIGAR 先记两条加法法则，再对算例：**查询消耗（read 占多少碱基）= M + I + S；
     参考跨度（参考坐标跨多少）= M + D**（I 与 S 不占参考，D 不占 read）。
     `50M2D10M` → 查询 `50+10=60` bp、参考 `50+2+10=62` bp；`10S130M2I8M` →
     查询 `10+130+2+8=150`、参考 `130+8=138`；`60M` 配 `NM:i:3` → CIGAR 数错配
     得 0、NM 得 3——**NM 是错配＋插入＋缺失的总数，不是错配数**（本例无 I/D 才恰
     为 3 错配；`50M2D10M` 配 NM:i:3 应拆成 1 错配 + 2 缺失）。
  3. 坐标：`ATGCA` 取 `TGC` = GFF3 `[2, 4]`（1-based 闭）= BED `[1, 4)`（0-based
     半开），长度都是 3；`chr1 1000 1200`（GFF3，201 bp）的正确 BED 是 `999 1200`，
     照抄成 `1000 1200` 得 200 bp、丢掉第 1000 号碱基（区间第一个），终点不变。
- **出错信号**：哪一条对不上 → 先重算手算（教材 §5.7 习题 6–8 就是这三组）；
  samtools 输出与教材不一致才怀疑环境版本（课程 pin 1.17；l0_04 步骤 2 有同输出
  实测记录，本机 1.22.1 复测同输出）。把 NM 当错配数、把坐标错位叫「整体左移/右移」
  都是教材 §5.5.3 / §5.5.1 点名的失效面。

## 5. 失效条件对照（教材 §4.5 与 §5.5，本实验里在哪一步察觉）

1. **Illumina 3′ 端质量下降被当成样本问题**（教材 §4.5.1）｜察觉：步骤 5 看真实
   Illumina 数据的质量字符（完整位置曲线在 u04 的 FastQC）。分 R1/R2、lane、run
   对比：普遍趋势是化学预期；中段突然塌陷或单条 lane 整体偏低**更像**运行问题——
   两类判断都要分层对照排查，不把任何单一曲线写成排他诊断；重提 DNA 排在最后。
2. **同聚区以插入缺失为主，投票/深度修不掉系统性偏差**（教材 §4.5.2）｜复现
   （绝对路径，任意当前目录可跑）：`python3 <课程仓库路径>/textbook/demos/
   ch04_homopolymer_indel.py --selftest`——L=6 纯随机区：0.769 → 51 次投票 0.039；
   L=7 系统偏差区：0.819 → 0.971、偏移仍 −1.00。对照面：`python3 <课程仓库路径>/
   textbook/demos/ch04_ccs_vote.py --selftest`——1/3/5/11 passes 残留错误率
   1.004×10⁻¹ → 4.000×10⁻⁵（p = 0.10 合成模型，只含替换、假设独立）。
3. **坐标混用让区间差一位而无人报警**（教材 §5.5.1）｜察觉：步骤 7 坐标 demo 的
   两组已知答案（`TGC` 双写法；`999 1200` 对 `1000 1200`）。三查：起点减一、终点
   不变、长度相等；全程无报错。
4. **用 CIGAR 数错配、把 `M` 当完全匹配或把 `NM` 当错配数**（教材 §5.5.3）｜
   机制：`M` 只表示「对齐」、不区分相同与错配；`NM` 是错配＋插入＋缺失的总数。
   后果：高估「完美比对」比例、把缺失算成 SNP，全程不报错。察觉：步骤 7 的三组
   锚点——`60M`+`NM:i:3` 按 CIGAR 数得 0、按 NM 得 3；`50M2D10M`+`NM:i:3` 只能
   拆出 1 错配＋2 缺失；本科层数错配读扩展 CIGAR 的 `=`/`X` 或把 SEQ 与参考逐位
   比，`NM` 只作总数校验。
5. **截断与折行「条数对而内容错」**（教材 §5.5.4）｜察觉：步骤 6 负例三连——
   截断与不等长被拦下（rc=5），中部缺行＋凑整静默（rc=0、打印「完成」）。防线是
   md5 对账＋提供方条数核对＋逐块结构校验三件一起做，不能指望任何单一脚本。
6. **（备选）行首计数让条数偏大**（教材 §5.5.2）｜察觉：步骤 3；`@` = Q31 是合法
   质量字符，换「行数 ÷ 4」独立口径对账。
7. **（备选）深度换不来跨度**（教材 §4.5.3）｜本实验只埋口径：步骤 4 的名义深度是
   「每个位点被扫几遍」，不增加单条读段的物理跨度；跨重复要靠读长，回收在 u06/u08。
